# DeepTutor Go 笔记同步

把 DeepTutor Notebook 中整理完成的笔记固化到本站 Go 文档，同时将运行数据、参考资料与可发布正文严格分开。所有命令都从仓库根目录执行。

## 检查数据源

优先使用技能自带的只读脚本，不要每次临时拼接 DeepTutor 数据查询命令：

```bash
bash .agents/skills/deeptutor-go-sync/scripts/inspect.sh notes Go
bash .agents/skills/deeptutor-go-sync/scripts/inspect.sh routes Go
```

只有在需要理解数据位置、选择学习路线或维护同步清单时，才读取[数据模型说明](references/data-model.md)。

脚本默认读取 `/srv/deeptutor/data`；若设置了 `DEEPTUTOR_DATA_DIR`，应优先使用该变量。数据目录或必要命令不可用时，说明具体缺失项并停止，不要修改站点文档。

不同数据源的用途必须区分：

- Notebook record 是可发布的笔记正文。
- Mastery state 只提供课程分组和学习顺序，不作为文章正文。
- `knowledge_bases/*/raw` 默认只是参考资料，除非用户明确要求，否则不发布。
- 不得导入设置、认证信息、聊天数据库、日志、记忆轨迹、生成的索引或无关 Notebook 记录。

## 增量对账

1. 检查 `git status --short`、目标目录和 `src/docs/language/go/.deeptutor-sync.json`，保留所有无关改动。
2. 列出候选笔记，再完整读取准备同步的记录：

   ```bash
   bash .agents/skills/deeptutor-go-sync/scripts/inspect.sh note <notebook-id> <record-id>
   bash .agents/skills/deeptutor-go-sync/scripts/inspect.sh note-hash <notebook-id> <record-id>
   ```

3. 确认适用的 Mastery Path。清单中记录的路线仍存在且主题匹配时优先沿用；若多条路线会产生实质不同的章节顺序，先请用户选择。
4. 用 record ID、源内容哈希和上次同步后的目标文件哈希与同步清单对账：
   - 源哈希和目标哈希都未改变：不修改。
   - 只有源哈希改变：刷新已映射页面。
   - 只有目标文件哈希改变：视为仓库内人工编辑，保留并报告，不回写同步哈希；本轮教学质量审阅产生的改动除外，见下文。
   - 源和目标都改变：先查看 Git 历史并做三方对账，不直接覆盖。
   - 出现新的相关 record：新增页面和映射。
   - 已记录的源 record 消失：报告异常；除非用户要求下架，否则不删除页面。
   - 新笔记看起来是旧笔记的重写版：同时阅读两者，再判断替换、合并或并存。
5. 删除或重命名页面前，搜索仓库中的入站链接。同步授权不自动包含删除或提交；仅在用户明确要求时执行。

## 转换为站点页面

保留 Notebook 的实质内容，但移除 DeepTutor 展示层包装，例如开头的 `**Note:**` 摘要、紧随其后的分隔线，以及 frontmatter 已提供标题时重复的一级标题。

页面使用以下结构：

```yaml
---
title: 清晰、简洁的标题
icon: /assets/icons/article.svg
order: 1
category:
  - Go
date: YYYY-MM-DD
---
```

沿用仓库现有的 snake_case 文件名。已经写入清单的目标文件名保持稳定，除非重命名有明确收益。默认一条 Notebook record 对应一篇页面；只有用户要求或多个 record 明确属于同一主题的连续修订时才合并。

页面 `order` 取自选定的 Mastery Path：先按 module 的 `order`，再按 `knowledge_points` 数组顺序。单篇笔记覆盖多个知识点时，放在它覆盖的最早知识点位置。只排列已经同步的页面，不为缺失知识点创建占位页。用户要求“只保留笔记内容”时，应下架旧的重叠正文，不要悄悄混入旧稿。

## 单章节主题覆盖审计

在教学质量审阅前，先根据该页面标题、Notebook 正文和对应 Mastery Path 知识点，为**每一篇新增或刷新页面**列出其主题应包含的最小知识链。不要用页面长度、标题数量或整条课程路线的完成度代替这项审计。

逐项确认该章节是否已经讲清：核心概念与术语、基本语法或典型用法、发生机制和前置条件、与相近概念的区别、常见误用及其可观察后果，以及该主题必要的工程边界（错误、资源、并发、性能或版本条件）。只有名称出现或给出孤立代码片段不算覆盖；缺少会使读者形成错误心智模型的环节，必须标为缺口并补足。

主题边界由该章节的学习目标决定：应完整解释该主题直接相关的知识，不把应由后续独立章节系统讲解的内容硬塞进来。若有意不展开相邻主题，应保留清晰边界或链接到对应页面；不得用“课程其他地方会讲”掩盖本章必须的前提或限制。交付时简要说明每篇审阅后补齐的关键点和仍刻意留给相邻章节的范围。

## 初学者叙事与前置检查

站点页面面向初学者时，按从上到下的首次阅读路径审阅，而非只检查事实是否正确。每篇新页面应在开头用简短语言交代本章要解决的问题、读者已经需要会什么，以及首次阅读应先掌握哪些部分。首章不假定已有语言基础；若本章必须使用尚未单独讲过的语法或概念，先给出完成当前例子所需的最小解释，再逐步扩展。

每个新术语、符号或 API 都应在第一次使用前或紧邻首次使用处解释。示例从读者已掌握的变量、值和控制流出发，一次只引入一个新概念；不要为了补充“完整性”而突然带入接口、并发、编码、错误链、框架或实现细节。与主题相关但需要更多前置知识的内容可放在明确标记的“进阶/第二遍阅读”小节，说明何时再读；不要让它阻断首次理解。

审阅时特别检查：代码是否调用了尚未解释的函数或使用了未交代的 `if`、`range`、指针、包和错误处理约定；章节间跳跃是否给出承上启下的过渡；以及“为什么现在学习它、它解决什么问题”是否在代码细节之前说清。若缺失的前置知识无法用最小说明安全补足，应报告该课程依赖，而不是假装读者已经掌握。

## 教学质量审阅

每轮同步在写入页面后、更新清单前必须完成教学质量审阅。审阅范围是本轮新增或刷新页面，以及因同一概念而出现矛盾、过时前提或重复解释的已同步关联页面；不要求每轮无差别重写整个 Go 课程。

审阅时以改善学习效果为目标，重点检查：

- **正确性**：区分语言保证、实现细节与惯例；对 `defer`、并发、方法集、内存/别名、版本相关 API 等容易误解的语义，以 Go 规范、标准库文档或官方资料复核。需要版本条件时明确写出，不把偶然行为说成保证。
- **解释链条**：给出前提、发生机制与可观察后果；避免只有结论或口号。初学者常混淆的相近概念应直接对照，例如值复制与共享底层数据、可取地址的方法调用与接口方法集。
- **示例质量**：代码要能支持结论，标明必要的导入、前置状态或版本条件。完整程序必须可编译；片段需清楚说明其省略的上下文。对有陷阱的用法，补充最小反例和预期行为。
- **工程边界**：补足错误处理、资源释放、并发访问、封装和 API 兼容性等必要限制，但不要为了“全面”引入未在当前知识点使用的框架或实现细节。
- **课程一致性**：沿用术语与既有学习顺序；发现两个页面对同一规则给出冲突或可能误导的说法时一并修正。不要改变已映射页面的文件名、路由和 `order`，除非用户另行授权。

审阅发现问题时，直接优化站点页面，而不是回写或伪造 Notebook 原文。保持原笔记的主题和实质内容，删除重复展示层，补充准确解释、对照、例子或版本说明；无法从权威资料确认的结论应保守表述或报告给用户。对语义复杂的新增示例，可在临时目录编译最小程序验证其行为。

## 正式课程发布门槛

新建或刷新的页面在完成转换时只是待审内容，只有依次完成单章节主题覆盖审计、教学质量审阅、必要修正和验证后，才可视为正式同步的课程内容并更新同步清单。不得把“已从 Notebook 写入文件”报告为同步完成。

正式发布前确认：章节没有未处理的关键覆盖缺口或未经说明的边界，初学者首次从上读到下不会被未介绍的前置概念或突然出现的进阶主题阻断；事实与示例已通过必要的权威资料或最小编译验证；frontmatter、`order` 和入站链接保持有效；`synced_target_sha256` 是最终审阅后文件的哈希；以及本技能的验证命令通过。若任何一项无法完成，保留现有已发布页面和人工编辑，说明待解决问题，不更新该记录的成功同步状态。

教学审阅在本轮产生的页面编辑属于受控同步结果：完成后应将对应记录的 `synced_target_sha256` 更新为审阅后的文件哈希，保留原始 `source_sha256` 不变。仓库中已有、非本轮产生的人工编辑仍按增量对账规则保护，不得借审阅之名覆盖。

内容修改完成后，更新 `.deeptutor-sync.json` 中的路线、record 到文件的映射、源时间戳、原始正文哈希和同步后目标文件哈希。清单不得保存凭据、模型配置、聊天内容或机器相关的绝对路径。

## 验证结果

至少检查以下可观察结果：

```bash
rg --files --hidden src/docs/language/go
git diff --check
pnpm docs:build
git status --short
```

若依赖尚未安装，按现有锁文件执行 `pnpm install --frozen-lockfile` 后重试构建。确认被删除路径没有残留入站链接，同一目录中保留页面的 `order` 不重复。对于经过教学审阅而修改了代码示例或版本条件的页面，还应确认示例逻辑与正文结论一致；必要时运行最小、隔离的编译验证，并在交付时简要说明发现并修正的关键问题。用户没有要求时不要提交。
