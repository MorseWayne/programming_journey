# 10.12 审阅记录：维护性评估

DeepTutor BookEngine 八节初稿均 ready、无失败块；本地 HTTP Markdown 导出与引擎渲染 SHA256 一致。`original.md` 保留未经改写的完整初稿。正式页改写为面向 Go 初学者的八节递进课程，以待审 R9 的影响图和 22 道分层练习收束第十卷。

## 教学重组

- 先用“下一次安全改动”定义维护性，再把 R9 的 HTTP、领域、客户端、事件、测试和发布触点分为“改、验、不动”，最后讨论代码结构、行为保持、技术债和测量。
- 把 Go 字符串、字节和 rune 的计数讲成可手算的前置：`len("你好") == len([]byte("你好")) == 6`，而 rune 数为 2。请求原始正文 4096 B 与解码后消息正文 6 B 是不同对象。
- 先为当前 S2 `/v1` 建立 6 B、重复 409、非成员 404、`accepted_in_memory` 的刻画用例；重构必须保持这些行为。只有 R9 获批、明确新合同后，才考虑 9 B 能力。
- 技术债按权限泄露、权威事实重复、旧接口漂移、风格摩擦排序，明确这是纸上假设，不是对本仓库或 OpenIM 的缺陷宣称。

## 技术修订

- 生成请求将 `len(body)` 与 `len([]byte(body))` 写成“口径不一致”，初稿也有“不同写法会分叉”的含糊叙述。对同一个 Go `string`，两者**同为字节数**；真正不同的是 `utf8.RuneCountInString` / `len([]rune(...))` 的 code point 数。正式页和练习 2、3、10 已明确纠正，依据 Go 语言规范和 Go 官方字符串文章。
- 初稿多处把 R9 直接写为修改 **S2/v1** 的既有 6 B 合同，甚至举 `S2_V1_BODY_MAX_UTF8_BYTES = 9` 和“7–9 B 原拒绝变接受”的行为保持例子。这与 R9 尚待批准、旧 `/v1` 应保持 6 B 的课程合同冲突。正式页把未来 9 B 限定为获批的新版本/能力，并将当前行为保持重构与未来功能变更分成两步。
- 初稿把 S3 存储提议描述成“可切回内存实现”的普通回退，容易把 `stored_in_teaching_db` 与 `accepted_in_memory` 混为同一承诺。正式页强调这是独立合同，历史 9 B 消息和数据迁移须另审；不能仅恢复旧常量或切换存储路径就宣称安全回退。
- 初稿还混入未核实的教学内存记录容量 `200`，正式页没有据此推导 HTTP 合同。4096 B 仅指原始 HTTP **请求正文**，不指完整报文。
- 固定 OpenIM 两处源码只支持发送到 MQ 与 Mongo 消费分处异步边界，不推断整仓维护性评分、真实 R9 影响、生产者确认级别或设备交付。
