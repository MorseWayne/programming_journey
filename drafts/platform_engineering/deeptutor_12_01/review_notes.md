# 12.01 审阅记录：运行环境与制品

## 教学重组

- 源提交 C、Go 工具链/依赖/生成代码、二进制 B、镜像 digest D1、tag T、运行配置 K、平台架构 A 与外部数据 S 各自有不同的证据责任。当前仓库没有因此新增或运行在线 IM 服务。
- tag 可指 D1 或 D2，digest 按相应内容寻址；多平台 index digest 和所选平台 manifest digest要分开。相同 D1 也可能因 K、权限、DB/卷状态与平台资源而有不同业务结果。
- `go.sum` 用于模块内容校验，不是完整锁文件；`ReadBuildInfo` 只提供条件具备时的部分嵌入构建线索。镜像层与数据库/卷/进程内 S2 状态分开。
- 当前 `/v1` 仍最多 6 UTF-8 B、重复 409、非成员 404、200 仅内存受理；R9 9 B 待审且 S3/v2 DB 提议独立，配置不能偷偷放宽旧合同。

## 技术修订

- 初稿把 `go.mod`/`go.sum` 一起说成“锁定的版本与校验和”。正式页按 Go Modules Reference 说明 `go.sum` 可能含不用的版本、并不锁完整构建；工具链、生成代码、私有/本地依赖与运行数据要另留证。
- 初稿将 S3/v2 的存储提议写成“R9 待审状态”，以及给出“S1 数据库已完成迁移”等本系列没有的前提。正式页严格分开当前 S2、独立未来 S3 与正文 6→9 B 的待审 R9，不虚构已迁移数据库。
- 初稿多处假定 S2 已有在线镜像、接口响应、启动审计端点，甚至建议直接部署/扫描制品。正式页明确当前为静态课程；构建、镜像摘要、运行结果均是未来学习者个人隔离实现的待测事项。
- 初稿有把 tag T 和 manifest digest 混称“同一版本”、把同 index digest 的多架构运行内容当同一镜像字节的风险。正式页让学习者记录实际平台与解析出的 manifest；摘要不锁启动配置/外部数据。
- 初稿给出了具体构建与运行秘密处理命令。正式页只解释 Docker 官方机制与最少权限，不放真实凭据或执行构建/部署。
- 固定 OpenIM 两处源码只支持发送返回与 Mongo 消费的异步边界，不证明镜像、工具链、集群、秘密或本课程网关的运行身份。
