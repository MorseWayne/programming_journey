# 08.09 审阅记录：可靠任务与调度

DeepTutor BookEngine 八节初稿均 ready、无失败块；本地 HTTP Markdown 导出与引擎渲染 SHA256 一致。`original.md` 保存完整初稿。正式页以通知任务 `N9=notify:u-b:d-b1:m-9:v1` 为线索，按身份、持久状态、短事务认领、结果未知、有限重试、容量顺序、运维对账和 22 题重组。

## 教学重组

- `m-9` 消息身份、E9 事件身份、N9 稳定任务身份与 A1/A2 执行尝试分别定义；任务过期/失败不删除权威聊天历史。
- `READY→LEASED(W1,token41,A1)→PROVIDER_ACCEPTED/RETRY_AT/REPAIR_REQUIRED/CANCELED` 只描述任务；提供方接纳、B 设备收到与已读各需独立证据。
- PostgreSQL `SKIP LOCKED` 仅作为短事务候选领取工具；W2 接管 token42 后 W1 不可迟到写任务状态，但已发生的外部推送并不会被行更新撤销。
- 先标完成再发造成漏尝试，先调用外部再标完成可能重发；A1 提供方已接纳但回应丢时保留“结果未知”，W2 沿同一 N9 身份受控重试。
- 玩具三次**总**处理尝试包含首次，区分领取未调用、已调用未知、暂时/永久错误；进入修复状态须留脱敏责任与对账入口。B 25 小时离线越过玩具 broker 24 小时保留时仍按权限从权威历史补拉。

## 技术修订

- 原稿多个段落把任务“完成”或 Worker 条件更新成功顺手写成“已送达”；正式页统一 `PROVIDER_ACCEPTED` 只证明提供方接纳，不证明 B 的设备接收、展示或已读。
- 原稿有以当前 `lease_until>now` 查询作外部动作前安全证明的倾向。正式页说明 SQL 条件更新仅保护任务行；外部提供方已发生的效果、超时回应和直接网络字节仍可能重复/未知。
- 原稿把 token 围栏和目标去重写得过于通用；正式页把提供方幂等键限定为**若其协议确实支持并配置**，否则依设备稳定 ID 去重/权威补拉并承认网络重复可能。
- 原稿多个场景以“第几次发送”为尝试计数，忽略领取后尚未调用就崩溃。正式页要求 attempt 记录领取、实际调用和结果阶段，避免三次预算与实际网络次数混同。
- 旧 v1 任务、撤回/删除和当前成员权限在执行时重核；取消在线提示不等于撤销已发生推送或删除权威消息。
- 固定 OpenIM 两段源码只能证明所述发送入队返回与另一 MongoDB 消费路径，不能证明 N9 任务表、租约或提供方幂等协议实际存在。
