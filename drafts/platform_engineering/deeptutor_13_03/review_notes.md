# 13.03 审阅记录：模块与信息隐藏

DeepTutor BookEngine 八节初稿均 ready、无失败块；本地 HTTP Markdown 导出与归档的 `original.md` SHA256 一致。正式页用虚构 IM 发送和历史补拉接口，讲模块公开承诺、变化来源、信息隐藏、Go 消费侧接口、异步确认和变更冲击，附 22 道分层练习。

## 教学重组

- 先区分接口的输入/结果/错误承诺与模块内部选择，再用 Parnas、Ousterhout 的变化决定和深模块解释为何要隐藏表名、队列 offset 和分配策略。
- 对照让 HTTP 层编排成员校验、序号、Mongo 和 broker 的泄漏式流程，与提交业务意图、明确确认边界的语义型 Send 纸上接口。
- 用 Go 消费侧接口建议和用例包、领域规则、存储/事件适配器的责任表说明依赖方向；不为每个结构体或 mock 造接口。
- 用 R9、S3、E9、成员历史规则和 B 多设备 ACK 的变更冲击卡区分可隐藏实现与必须公开的业务合同。

## 技术修订

- 初稿导出有重复 `###` 标题和同义重述；正式页重排为接口→变化→发送对照→Go 边界→结果不确定→泄漏反例→评审卡。
- 初稿后段把 R9 错写成“审核中/已拒绝”的审批状态机。本系列 R9 是**正文上限 6→9 UTF-8 B 的待审提议**；正式页只按该含义讨论输入、协议与兼容。
- 初稿 `HistoryReader.ReadAfter` 用 `MessageID` 作为 `after` 游标，容易把稳定消息意图与会话内顺序位置混为一体。正式页沿 13.02 的 `(conversation,seq)` 补拉语义，不把 broker offset 或消息 ID 当连续游标。
- 初稿几处提出“客户端以相同 `message_id` 重试，服务端返回既有结果”，若被读成当前 `/v1` 行为就违反同 ID 重复 409。正式页将未来查结果/重试策略标为待设计，当前 409 保持不变。
- 初稿对 S3 权威范围延伸到成员和会话、对 broker 换型和 outbox 恢复能力作了未经证实的推断。正式页只写未来教学消息 DB 存储提议和可评估的实现边界，不声称已有事务、outbox、完整 ACK 或可替换性。
- 固定 OpenIM 两处源码只支持所读发送调用 MQ 与另一 Mongo 消费路径的异步边界，不能判断其所有模块接口优劣、完整确认语义或部署选型。
