# 13.02 审阅记录：领域与状态建模

DeepTutor BookEngine 八节初稿均 ready、无失败块；本地 HTTP Markdown 导出与归档的 `original.md` SHA256 一致。正式页以虚构 IM 的发送、历史补拉、设备确认和成员变更用例，解释实体/值对象、身份、不变量、状态轴、连续游标与聚合边界，附 22 道分层练习。

## 教学重组

- 先从四个用例找业务名词与前后条件，再给实体/值对象定义，避免初学者从 SQL 表或 Go `struct` 误推领域模型。
- 建身份账本，分开每次 HTTP `request_id`、稳定消息意图 `message_id`、未来会话内 `seq`、稳定事件 E9、broker `P0 offset42`、设备确认键。
- 当前 S2 `/v1` 的 6 B/4096 B/409/404/200 与未来 S3 权威唯一约束分表说明；当前 409 不证明跨 Pod/重启后持久去重。
- 将权威消息、事件、各设备 ACK 与阅读拆成独立状态轴；用“连续到 7、先见 9 缺 8”手推游标仍为 7。
- 用重试、权威已存事件未发、设备缺序和非成员补拉四类反例审不变量与聚合边界，拒绝无界的 Conversation 大聚合。

## 技术修订

- 初稿导出有大量重复 `###` 标题及同义重述；正式页按用例→身份→不变量→状态→游标→聚合逐层组织。
- 初稿后段称“当前 S2 已约束发送、持久化、事件与设备确认”，与本系列 S2 `accepted_in_memory` 冲突。正式页明确当前没有权威 `seq`、E9 与设备 ACK 能力；S3 仍是待审教学 DB 提议。
- 初稿有把 Outbox 的恢复能力写成既定保证的段落，正式页只把持久约束、事件恢复、outbox 或等价机制列为未来可评估的设计选择，不宣称实现。
- 初稿个别练习写“S2 当前已读”“S3 未来必读”，错把阶段名当消息阅读状态；正式页只把阅读作为独立未来状态轴，不与 S2/S3 阶段混用。
- 初稿多处说聚合根决定表、事务和事件方案，或将 Conversation/Message/DeviceProgress 分组写成确定架构。正式页只给以不变量为依据的**候选责任边界**，并指出数据与部署映射仍需负载、并发和产品规则证据。
- 固定 OpenIM 两处源码只支持所读发送调用 MQ 与另一 Mongo 消费路径的异步边界，不证明本章聚合、SQL 唯一约束、outbox、ACK 或设备游标。
