# 06.04 审阅记录：页与缓冲池

## 教学重组

- 先区分业务消息、数据库页、OS 虚拟内存页，再介绍页头/槽/记录/空闲区；真实 PostgreSQL/SQLite 页格式仅作为机制依据，不把四条每页的玩具密度误称引擎参数。
- 固定 seq1..64→P0..P15 共 16 页，`[5,8]` 与 `seq<9 DESC LIMIT4` 的目标**数据页**均为 P1；索引定位、权限、执行计划和可能的外置页另计。
- LRU 容量 2、从空开始，序列 P0,P1,P0,P2,P1 得 4 miss、1 hit、2 eviction；两页同时 pinned 时 P2 不能直接覆盖，dirty 写回与事务提交另行区分。
- 22 道题从页词汇、范围结果到缓存来源与存储引擎口径逐步反馈。

## 技术修订

- 原稿使用了 `A/B/C`、`P0/P1/P2` 两套替换序列，又在 pin 反例中临时改用容量 3 的 P0/P1/P2。正式页固定容量 2 和同一 P0/P1/P2 图例，命中/淘汰可逐项对账。
- 原稿有 PostgreSQL 采用近似时钟扫描、WiredTiger 综合冷热/脏页等具体替换描述；正式页只据本章已核对的官方文档说明各引擎缓存层与页机制，**不**把玩具 LRU 或未核对的内部细节断言为其实际算法。
- 64 条每页 4 条是理想布局；真实行宽、页头、更新、索引页及外置内容会改变页数。结果位于 P1 不证明整条 SQL 只触一页或数据库一定选索引。
- buffer miss 表示数据库内部池里没有页，OS 文件缓存仍可命中，因此 4 miss 不等于 4 次物理盘读；PostgreSQL `EXPLAIN BUFFERS` 的 shared hit/read 也不是设备 I/O 次数。
- pin 表示当前使用不可驱逐，dirty 表示页已修改未按协议写回；dirty 数据页写回不等于事务刚提交，WAL 与崩溃恢复留 06.09。
- MongoDB WiredTiger 官方文档只支撑“内部缓存与文件系统缓存共同存在”等通用对照，不映射本章 P0–P15 到 OpenIM 实际 MongoDB 页面。
