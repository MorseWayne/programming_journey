# 13.10 审阅记录：技术债与演进

DeepTutor BookEngine 八节初稿均 ready、无失败块；本地 HTTP Markdown 导出与归档的 `original.md` SHA256 一致。正式页借虚构 IM 协议演进讲技术债利息/本金、现行缺陷与范围限制分类、证据排序、架构/配置漂移、小步偿还和收益复测，附 22 道分层练习。

## 教学重组

- 从 Fowler 的隐喻讲“以后碰到该处多付的变更/故障代价”，再把当前合同缺陷、S2 明示范围、S3 未来阻断、新功能与**待证技术债**分栏。
- 用未来六次同类变更各多 3 人时、局部整治估 12 人时，算纸上 18 人时利息/6 人时可能净省，说明频率、回归和事故风险可推翻结果。
- 先以 `/v1` 7 B/409/404/200 违规和已确认消息不可读作为止损硬门，再按变化频率、额外成本、事故风险、偿还投入和可验证性排序维护问题。
- 区分 proposed ADR、已接受后未经评审的架构/合同漂移，以及 12.11 Git 目标与 Pod 生效配置差异；小步整治需有 owner、契约反例、停止/回退与后续复测。

## 技术修订

- 初稿导出有重复 `###` 标题和多次同义重述；正式页重排为债务定义→分类→取证算式→优先级→漂移→偿还→反馈。
- 初稿中段把 S3 解读为对象存储/附件权威，讨论 URL、私有桶与 `resource_id`，偏离本系列 S3 未来教学消息 DB 的固定含义。正式页只沿 IM 消息 `m-9/seq9/E9` 和旧端协议展开。
- 初稿后段把当前 S2 回执说成“已持久化”，将 S3/R9 改作历史重试兼容路径，又说当前合同未定义同 ID 重试。正式页固定 S2 `accepted_in_memory`、同 ID 重复 409、S3 DB 存储提议和 R9 6→9 B 待审。
- 初稿把 `7A/7B` 当作旧版字段/阶段，还主张某些 `/v1` 7 B 接纳可由 ADR 正当化。当前 `/v1` 6 UTF-8 B 上限是硬合同；正式页将 7 B 接纳一律列当前缺陷，R9 未批前不豁免。
- 初稿有 `6×3=18` 一会儿表示人时、一会儿表示组合路径的混算。正式页只将其用作**虚构六次同类变更×每次额外三人时**，并明确不是测得收益。
- 固定 OpenIM 两处源码仅支持所读发送调用 MQ 与另一 Mongo 消费路径的异步边界，不能证明真实债务、故障频率、组织等待或偿还 ROI。
