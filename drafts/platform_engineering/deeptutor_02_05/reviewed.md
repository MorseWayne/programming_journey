## 本章从哪里开始

本章采用两个**分开的教学契约**：

1. **只按 `Seq` 排序**：同 `Seq` 的记录比较结果并列；若希望保留本次输入的相对次序，使用稳定排序。
2. **按 `(Seq, MessageID)` 排序**：先比 `Seq`，相同时以稳定且唯一的消息 ID 打破并列；给定相同的一组有效记录，不同输入排列可得到同一输出次序。

## 一、排序前先定义比较键

一条消息可以同时具有 `MessageID`、`Seq`、`DisplayTime` 和当前切片下标。它们回答不同问题：

| 字段 | 在本章回答什么 | 不能由它直接推出什么 |
|---|---|---|
| `MessageID` | 这是哪条消息 | ID 字典序未必是发送先后 |
| `Seq` | 本模型采用的主排序键 | 缺号是否表示丢消息 |
| `DisplayTime` | 给人看的时间文本 | 客户端时钟一定可信或跨设备全局有序 |
| 切片下标 | 本次输入的当前位置 | 持久消息身份或稳定游标 |

先固定虚构输入：

| 输入位置 | 消息 ID | `Seq` | 显示时间 |
|---:|---|---:|---|
| 0 | `m-d` | 5 | `09:30` |
| 1 | `m-b` | 2 | `09:31` |
| 2 | `m-c` | 4 | `09:29` |
| 3 | `m-a` | 2 | `09:32` |

若只按 `Seq` 稳定排序，结果是 `m-b(2), m-a(2), m-c(4), m-d(5)`：两个 `Seq=2` 保持输入中 b 在 a 前。若按 `(Seq,MessageID)` 排序，结果是 `m-a(2), m-b(2), m-c(4), m-d(5)`：a、b 的次序由明确的次级键决定。这两种结果都能按照各自契约正确排序，不能用“稳定”和“确定”互相替代。

若同一个 `(Seq,MessageID)` 在输入中出现两次且内容不同，比较器无法代替去重或冲突处理。进入“给同一消息集合确定唯一展示次序”这个结论前，应先定义并验证消息身份范围与重复记录的处理规则。

## 二、严格比较、稳定性和跨输入确定性

Go 的排序回调 `less(i,j)` 回答“位置 i 的元素是否**严格**排在位置 j 前”。它必须自洽：任何元素都不能小于自己；若 a 在 b 前，b 就不能也在 a 前；先后关系还要满足传递性。最容易看出的错误是写成 `a.Seq <= b.Seq`，同一元素会被判为“小于自己”。

比较 `(Seq,MessageID)` 时先比较主键，再比较次级键。下面是片段，`Message` 类型及完整程序在第三节给出：

```go
func lessMessage(a, b Message) bool {
	if a.Seq != b.Seq {
		return a.Seq < b.Seq
	}
	return a.MessageID < b.MessageID
}
```

当两个字段都相同时，两种方向的 `lessMessage` 都返回 `false`。不能为了“让算法继续走”而在完全相等时任意返回 `true`。比较器也不应在比较时修改被排序切片，或依赖每次调用都会变化的时钟、随机数。

**稳定排序**只保证比较器视为相等的两个元素仍保持本次输入中的相对位置。例如输入甲为 `m-b(2),m-a(2)`，输入乙为 `m-a(2),m-b(2)`；两次只按 `Seq` 稳定排序，输出仍分别为 b,a 与 a,b。两次都稳定，却不相同。

**跨输入确定性**来自足够完整、稳定的比较键。在两条 ID 都唯一且固定的前提下，按 `(Seq,MessageID)` 比较，输入甲和乙都会排成 a,b。这个规则便于复核和分页展示，但不赋予字典序任何因果含义。若业务恰恰要求“同序号保持日志中原先次序”，就应保存日志位置或采用可信输入次序，并选择稳定排序，而不是擅自添加 ID 次级键。

## 三、插入排序：维护有序前缀

像整理手牌一样，每轮从未排序后缀取出一条消息，将它插入左边已排好的前缀。外层处理下标 `i` 之前，`[0,i)` 已按比较器有序；初始 `i=1` 时单元素前缀自然有序。

先只比较 `Seq`，跟踪 `[5/A, 2/B, 4/C, 2/D]`：

| 本轮取出 | 前缀中右移什么 | 本轮结束的有序前缀 |
|---|---|---|
| `2/B` | `5/A` | `[2/B,5/A]` |
| `4/C` | `5/A` | `[2/B,4/C,5/A]` |
| `2/D` | `5/A`、`4/C`；遇 `2/B` 停止 | `[2/B,2/D,4/C,5/A]` |

相等的 `2/B` 没有右移，所以 B 仍在 D 前。比较时使用**严格大于**，是这版插入排序稳定的关键；若把相等项也右移，D 可能越过 B。

下面是一个完整独立程序：业务键已明确选择 `(Seq,MessageID)`，所以同 `Seq` 时 a 会按 ID 排在 b 前。它与上面“只按 Seq”的稳定性演示有意使用**不同比较契约**。

```go
package main

import "fmt"

type Message struct {
	MessageID string
	Seq       int64
}

func lessMessage(a, b Message) bool {
	if a.Seq != b.Seq {
		return a.Seq < b.Seq
	}
	return a.MessageID < b.MessageID
}

func insertionSort(messages []Message) {
	for i := 1; i < len(messages); i++ {
		current := messages[i]
		j := i - 1
		for j >= 0 && lessMessage(current, messages[j]) {
			messages[j+1] = messages[j]
			j--
		}
		messages[j+1] = current
	}
}

func main() {
	messages := []Message{
		{MessageID: "m-d", Seq: 5},
		{MessageID: "m-b", Seq: 2},
		{MessageID: "m-c", Seq: 4},
		{MessageID: "m-a", Seq: 2},
	}
	insertionSort(messages)
	for _, message := range messages {
		fmt.Println(message.Seq, message.MessageID)
	}
}
```

静态预期顺序为 `2 m-a`、`2 m-b`、`4 m-c`、`5 m-d`。内层每次把比 `current` 更大的元素右移，终止时 `current` 放在空位；因此有序前缀从 `[0,i)` 扩大为 `[0,i+1)`。初始、保持和外层走到 `i=n` 共同说明整个切片最终有序，且元素仅被移动，没有凭空添加或删除。

已基本有序时，内层很快停止，比较次数接近 n；逆序时，第 i 项可能跨过前面的 i 项，累计移动约 `1+2+…+(n-1)`，即 O(n²)。只保存当前消息和下标，额外元素空间 O(1)。这是适合小批或近有序输入的教学与局部工具，不宜把它直接用于巨大乱序历史的全量整理。

## 四、归并排序：分解后合并两个有序段

**分治**先把大问题拆成较小且相同形式的问题，再把子结果合成答案。归并排序将 `[lo,hi)` 分为两半，递归分别排序；长度 0 或 1 是不需再拆的基例。最后的关键工作是：把两个**已经有序**的段合并，而不是直接拼接。

```text
输入 [5/A, 2/B, 4/C, 2/D]
拆分 [5/A,2/B] 与 [4/C,2/D]
各自排序为 [2/B,5/A] 与 [2/D,4/C]
合并得到 [2/B,2/D,4/C,5/A]（只按 Seq 时）
```

合并时各有一个指针指向左右段尚未取出的首项。每轮取比较键较小者；一段耗尽后，把另一段剩余的有序项直接接到输出。若键相等而要求稳定，应**先取左段**：左段中的元素在原输入里位于右段之前，于是同键相对次序得到保留。

| 左端 | 右端 | 选谁 | 当前输出 |
|---|---|---|---|
| `2/B` | `2/D` | 左，因相等时保留先到者 | B |
| `5/A` | `2/D` | 右 | B,D |
| `5/A` | `4/C` | 右 | B,D,C |
| `5/A` | 右段空 | 左段剩余 | B,D,C,A |

每一层合并处理的元素总数约为 n，拆分深度约为 `log₂ n`，因此本模型时间 O(n log n)。典型数组归并需要 O(n) 的辅助元素空间，递归调用栈另有 O(log n) 层。若只写“分治所以快”，却没有计入合并与额外空间，就无法与其他方案比较。

归并的正确性可分两步说明：基例中的空段、单元素段有序；假设两个较短子段已正确有序，合并每次从两段当前最小者中选更小项，得到的前缀始终是全部未取元素之前的最小序列。所有元素被取完后，大段有序；相等时先取左段还额外保持稳定性。

## 五、快速排序：分区成本与退化

快速排序也使用分治，但先**分区**：选一个枢轴，在明确比较规则下，把较小或相等的元素放左侧、较大的放右侧，使枢轴处于分界位置，再递归处理两边。分区一次需要扫描当前子段；递归子问题必须严格小于原区间，否则无法保证结束。

用数值键 `[4,2,5,2,3]`、枢轴 3 的一个纸面分区结果是 `[2,2,3,4,5]`。这一步恰好看起来整体有序只是输入较小；一般分区只承诺左区不大于枢轴、右区不小于枢轴，两区内部仍可能无序。随后还要递归排序左右区。

| 分区形状 | 大致层数 | 本章的成本结论 |
|---|---:|---|
| 多数轮接近对半 | O(log n) | 每层扫描合计 O(n)，总 O(n log n) |
| 连续分成 0 与 n−1 | O(n) | 每层仍可能扫描许多项，总 O(n²) |

平均或期望 O(n log n) 需要对枢轴选择或输入分布作说明；不能把它写成所有输入的上界。一个总选首元素的朴素实现遇到已排序输入，可能持续极不平衡。普通原地快排通过交换元素，通常不稳定；相等键多时怎样分组也影响实际成本。这里不把 Princeton 的 Java 代码或某个朴素分区方案称为 Go 标准库 `sort.Slice` 的具体实现。

快速排序可能只需要较少的额外元素数组，但仍有递归栈；均衡时深度约 O(log n)，极端情况下可达 O(n)。这些空间条件也要与归并的 O(n) 辅助数组比较。

## 六、Go 标准库排序：两个不同合同

`sort.SliceStable` 保留比较器视为相等的元素在**当前输入中**的相对次序。若只按 `Seq` 排序，可以写：

```go
sort.SliceStable(messages, func(i, j int) bool {
	return messages[i].Seq < messages[j].Seq
})
```

`sort.Slice` 不承诺这种同键稳定性。若本章选择 `(Seq,MessageID)` 并已验证 ID 的稳定唯一范围，可用：

```go
sort.Slice(messages, func(i, j int) bool {
	if messages[i].Seq != messages[j].Seq {
		return messages[i].Seq < messages[j].Seq
	}
	return messages[i].MessageID < messages[j].MessageID
})
```

两个片段都应放在已有 `messages []Message` 的函数中，并导入 `sort`；它们不能被拼成同一轮连续排序后再拿输出比较两种合同。回调在排序过程中会被多次调用，应该只按不变字段比较，不在里面写入消息、调用时钟或更改切片。

标准库调用会重排传入的切片；切片若与其他视图共享底层数组，其他视图可能观察到元素变化。要保留导入前的原始次序，应先复制切片再排序。排序后还需核对：元素数不变、消息身份集合不丢不重、结果相邻键有序。只看“首尾值正确”不足以发现中间记录遗漏或同键被错误交换。

02.03 的二分查找只能在按其查询谓词所需的键有序时使用。按 `DisplayTime` 排序后，不能无条件按 `Seq` 二分；而按 `(Seq,MessageID)` 排序后的切片仍按 `Seq` 非降序，可用 `Seq` 的单调谓词找范围边界。查询和排序必须共享同一套可解释的顺序前提。

## 七、何时整体排序、何时维护索引、何时分块

若一次性读入 n 条记录，然后只展示或查询少数次，先收集再整体排序的典型比较成本为 O(n log n)。若每来一条都插入一个一直有序的切片，二分定位插入点可以很快，但中间插入仍可能搬移 O(n) 项；连续 n 次杂乱插入的移动总量可到 O(n²)。当范围查询频繁，才值得考虑维护有序索引，具体树结构与存储执行在后续章节展开。

输入文件大到无法一次装进内存时，**外部排序**先读入能容纳的小块，分别排好并写成临时有序段，再按相同比较规则归并各段。此时主要成本除比较外还有磁盘读取、写入、临时空间与打开文件数；每个文件的关闭、失败后的临时段清理也要有负责人。本章只建立这个入口，不给没有磁盘预算和错误恢复合同的“直接替换历史文件”示例。

排序结果的保证始终有边界：它为**当前取得的记录**给出按所选键的次序，不补出缺失消息，不证明客户端时钟真实，也不能把不同会话的本地时间自动变成全局因果顺序。若排序键来自服务端，仍要按具体协议核对其范围、唯一性和可见性。

## 八、排序方案评审与分层练习

| 需求 | 比较键与方法 | 关键前提 | 代价与局限 |
|---|---|---|---|
| 保留本次输入中同序号记录的先后 | 只按 `Seq`，稳定排序 | 原输入次序有意义 | 不产生跨不同输入的唯一结果 |
| 给同一组不同 ID 记录确定次序 | `(Seq,MessageID)` 完整键 | ID 稳定且按约定唯一 | 字典序只是裁决规则，不是真实先后 |
| 小批、近有序修正 | 插入排序 | 数据规模小 | 最坏 O(n²) 移动 |
| 大批、要求稳定 | 归并思路或稳定库函数 | 有辅助内存预算 | 典型数组归并需 O(n) 辅助空间 |
| 大批、已定义完整键 | 合适的库排序 | 比较器自洽 | 不从 `sort.Slice` 推断稳定性或具体算法 |
| 超出内存 | 分块排序加多路归并 | 磁盘、文件数与失败清理合同 | I/O 和临时空间成为主要约束 |

<details><summary>1. 只看 `MessageID` 能说明先后吗？</summary>

不能。除非协议明确让 ID 编码先后，本章只把它用作同 `Seq` 时的确定次级键。</details>

<details><summary>2. `less(a,a)` 能返回 true 吗？</summary>

不能。严格比较要求元素不小于自身；写成 `<=` 会破坏合同。</details>

<details><summary>3. 只按 `Seq` 稳定排序，相同 `Seq` 的记录怎样排列？</summary>

保持它们在**本次输入**中的相对位置。</details>

<details><summary>4. 两批相同记录输入顺序不同，稳定排序会自动给相同结果吗？</summary>

不会。若同 `Seq` 并列，稳定排序分别保留各自输入次序。</details>

<details><summary>5. 什么条件下 `(Seq,MessageID)` 能确定不同输入的同一结果？</summary>

比较器固定、自洽，ID 稳定且在比较范围内唯一，并先处理重复身份冲突。</details>

<details><summary>6. 按 ID 打破并列，能证明真实发送顺序吗？</summary>

不能。这只是可复核输出的次级裁决。</details>

<details><summary>7. 插入排序每轮开始时 `[0,i)` 有什么性质？</summary>

前缀已按所选比较器有序；本轮把第 i 项插入后扩大到 `[0,i+1)`。</details>

<details><summary>8. 只按 `Seq` 的稳定插入排序，为何相等时不右移？</summary>

后到的同键消息不应越过前面的同键消息；只有严格更大的项才右移。</details>

<details><summary>9. 插入排序完全逆序时怎样增长？</summary>

第 i 项可能跨过前面 i 项，累计比较和移动为 O(n²)。</details>

<details><summary>10. 归并排序什么时候停止递归？</summary>

子段长度为 0 或 1 时自然有序，直接返回。</details>

<details><summary>11. 归并左右两段首键相同，要稳定应先取哪边？</summary>

先取左段，保留输入中原先较靠前的同键记录。</details>

<details><summary>12. 典型数组归并的时间与额外元素空间？</summary>

时间 O(n log n)，通常需 O(n) 辅助数组，递归栈另计。</details>

<details><summary>13. 快速排序的一次分区后，左右两侧已各自有序吗？</summary>

不一定。只保证它们与枢轴的关系，仍需递归处理内部顺序。</details>

<details><summary>14. 朴素快排为什么可能退化到 O(n²)？</summary>

连续得到极不均衡分区，例如每次分成 0 与 n−1 项。</details>

<details><summary>15. `sort.Slice` 保证同键保留原次序吗？</summary>

不保证；需要这种合同时使用 `sort.SliceStable` 或定义完整次级键。</details>

<details><summary>16. 排序原切片会影响共享底层数组的其他视图吗？</summary>

可能。要保留原输入，先复制元素到独立切片。</details>

<details><summary>17. 按时间排序后能按 `Seq` 直接二分吗？</summary>

不能直接推断；必须先证明输出也按 `Seq` 非降序。</details>

<details><summary>18. 用二分找插入点后，中间插入就变成 O(log n) 了吗？</summary>

没有。定位可快，但搬移后续元素仍可能 O(n)。</details>

<details><summary>19. 外部排序的两大步骤是什么？</summary>

把可装入内存的块分别排序写成有序段，再按同一规则多路归并。</details>

<details><summary>20. 排序发现序号缺号，能自动补回缺失消息吗？</summary>

不能。排序只重排已有记录；缺号是否异常要按业务协议调查。</details>
