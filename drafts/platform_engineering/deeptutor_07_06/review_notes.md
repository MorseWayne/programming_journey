# 07.06 审阅记录：消息抽象

DeepTutor BookEngine 八节初稿均 ready，HTTP Markdown 导出与本地渲染 SHA256 一致。原稿保存在 `original.md`；正式页用一条未来教学 S3 已提交消息 `m-9/c-a seq9` 引出在线提示、搜索索引和离线历史三种不同需求，比较队列、Pub/Sub 与可回放日志，附 22 道练习。

## 教学重组

- 数据库消息 `m-9` 为权威业务事实，E9 是派生处理事件；当前 S2 `accepted_in_memory` 不被写成已部署 S3 数据库事务。
- 在线 B 提示可用 Redis Pub/Sub 的当前订阅分发作候选，离线错过后靠**权威消息历史与当前权限**补拉；发布成功不等于 B 设备接收/展示/已读。
- SearchIndex 组的 W1/W2 在一次投递中分担 E9；先 ACK 后索引写入有丢效果窗口，先索引写入后 ACK 有重投/重复窗口。按 `message_id` 与版本做幂等，ACK 不代表外部恰好一次效果。
- 教学日志中 E9 位于 partition P0、offset42；`m-9` 身份、`c-a.seq9`、offset42 分属不同编号域。SearchIndex/Notify 两逻辑组各需 E9，组内 worker 分担。分区内顺序不推成全局顺序。
- 玩具保留 24 小时、B 离线 25 小时后事件可能已清理；broker 不是无限历史。数据库提交→broker 发布之间仍有跨系统空窗，换消息产品本身不令两边原子。

## 技术修订

- 原稿一些段落把“离线补拉”主路径选为可回放 broker 日志，但本系列的权威历史在教学 DB，且保留期可短于离线时长。正式页让离线用户按权限和 `seq` 从权威历史补拉；日志主要服务有限窗口内派生重建与消费者重放。
- 原稿对组内 W1/W2 的表述有时像“E9 永远只会分配一次”；正式页限定为**某次投递中**分工，未 ACK 的任务可重新投递给同组 worker。
- 原稿用另一组 G/S3/D42/v17 例子多次切换角色，正式页固定 `m-9`、E9、`c-a`、P0/42、SearchIndex/Notify 与 B，避免初学者把网关 G、课程阶段 S3、会话身份混为一体。
- 消费 ACK、broker 发布确认、G 通知尝试与 B 应用/用户阅读分层；`XACK` 仅影响 Redis Stream 组内待确认状态，不代表永久消息历史或设备结果。
- 数据库已提交但 E9 未发布、E9 已发布但消费效果未确认、事件超过保留期都是不同失败；outbox 留 07.10，不在本章声称已部署。
