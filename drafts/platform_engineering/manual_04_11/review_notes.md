## 单章覆盖与教学审阅

- 用 RFC 5737 文档地址和 RFC1918 内网纸图说明本地链路下一跳、IPv4 ARP/IPv6 邻居发现、逐跳转发，不把 MAC/路由可达当应用身份或授权。
- NAT 内侧 `10.0.0.2:53000` 到外侧 `198.51.100.7:62000` 是地址/端口映射，不复制 N1/N2 进程内存；无固定 NAT 超时数字或用户身份断言。
- MTU1500、IPv4/TCP 最小头各20 的无选项纸上算式得1460 B 单包 TCP 数据；与原始 HTTP 体4096 B、当前 IM 正文6 UTF-8 B、TLS/HTTP/隧道开销分开。
- PMTU/大请求故障保留多种可能，不把“小请求过、大请求慢”直接定为 MTU；IPv6/PLPMTUD 概念按 RFC 前提表述。
- Wi-Fi/蜂窝切换可能改变 IP/NAT、旧 TCP/WebSocket 常需重连；QUIC 迁移受连接 ID/路径验证/端点条件限制，不能保证离线历史补齐或设备 ACK。
- 故障分类、阶段计时、隐私与业务确认共八节，22 题分地址、MTU/移动、诊断/业务三层。

## 原稿对账与修订

- 原稿主线使用文档服务 `203.0.113.10:443`、NAT 外侧 `198.51.100.7:62000`，中段又把服务换成 `203.0.113.20:443`，末段还写成客户端向 `198.51.100.7` 发送 IM 消息，把 NAT 外侧示例地址当成远端目标。正式页只用同一组文档地址和映射，按本地下一跳→NAT→服务端解释。
- 原稿把客户端切网后的“未确认发送”直接列为“幂等重试”步骤；当前 S2 同 ID 重复 **409**，`200 accepted_in_memory` 只到进程内存，连接恢复或新 NAT 映射不能证明原请求未执行。正式页只要求按实际传输与业务证据核对，不自动赋予重试保证。
- 原稿把网络位置也命名为 N1/N2，易与 04.09 的 IM 后端实例 N1/N2 混淆；正式页保持 A、网关/NAT、文档服务和业务后端各自独立的角色。
- 原稿正确复算 MTU **1500−20−20=1460 B**，也区分 HTTP 原始体 **4096 B**、IM 正文 **6 B**、PMTU 诊断与 QUIC 有条件迁移。正式页保留这些前提，并不把 1460 B 当业务消息或通用路径上限。
