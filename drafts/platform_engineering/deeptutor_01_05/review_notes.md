## 原稿修正与补充

1. 合并重复的身份、map、结构体定义和同质练习，改成概念一次定义、后续逐步复用。
2. 修正原稿“append 会改变已有元素下标”的泛化：尾部追加本身不使原有下标移动；重新排列、前部插入和过滤会改变位置。身份论证围绕这些确定变化展开。
3. 统一消息身份范围为会话内唯一；原稿有时示例全局唯一、有时会话内唯一，正文使用复合键与双层索引保持一致。
4. 补全原稿只列前两行却遗漏末尾空行和键数的预期输出；正文尽量按显式键读取，避免混淆 range 未指定顺序与 fmt 自身格式规则。
5. 明确 map make 参数是大小提示而非上限，map 没有 cap；nil、非 nil 空表、缺失键及存储零值分别解释。
6. map range 不承诺顺序，不被描述为每次必变化或独立随机洗牌；稳定展示由已有键切片决定。
7. 原稿 nil 对象表中写 `q == &Draft{}` 暗示“指向零值对象”，改为实际创建和字段判断；非零大小草稿的两个新对象地址不相等。
8. 指针比较只用非零大小具体类型与关系，不假造地址数字或推断零大小对象地址；业务 ID 与对象地址严格分开。
9. 补齐原稿正文章节未充分展开的返回局部变量地址示例；名字作用域结束与物理存储有效期分开，不断言永远在堆或栈。
10. 原稿 map 指针别名片段先删除键，之后再从已删除键取 old，却仍预测旧标题；正文重排为先持有旧指针、替换键、再删除，分别追踪旧别名。
11. map 值结构体的字段赋值和取地址按语言可寻址规则解释，不把某一版内部扩容搬迁实现当成语言保证。
12. 加入分层反例：map 值结构体含 slice 时，可通过其切片值修改共享元素，但不能直接赋新的切片描述。这补齐“不可寻址”与深层共享的区别。
13. 原稿再次把裸 `append(...)` 当作可运行但长度不变，正文统一要求接收结果，错误片段只放在清楚的编译错误语境。
14. 对确定的结构体复制和已有 slice 元素共享，去掉“通常”“可能”的含混用语；追加后是否仍共享则按显式容量分析。
15. 克隆只保证当前 map[string]bool 与 []string 字段的独立替换，保留 nil/空的策略是本题契约，不宣称通用深复制或只读/并发保证。
16. 原稿综合 Message 字段在 Body、Text、Content 间漂移，有函数读取未定义字段；统一为 ID、ConversationID、SenderID、Body 四个 string 字段。
17. 原稿 validateText 被改成单 bool，违背前章共同契约；恢复 bool/string 返回和原始文本检查次序，沿用 01.04 新增的 UTF-8 检查。
18. 原稿一处称修改内层 Messages map 后必须写回外层会话，与另一处示例自相矛盾；正文明确条目写入已经通过共享 map 可见，只有更换字段值才需外层写回。
19. 增加本地登记、成员 false/缺失、nil 集合、ID 一致性、重复身份和数量限制的明确规则，写入放在全部普通拒绝分支之后；拒绝不自动修复旧状态。
20. 综合程序保持会话分类检查先于正文校验；重复 ID 拒绝不被冒称完整网络幂等，输入 SenderID 不被冒称可信认证结果。
21. 合并后的程序把带修改效果的函数调用与读取结果的打印分成独立语句，避免依赖函数参数中非调用表达式的求值时序。
22. 给独立编写题提供“已有键可替换、新键受业务上限约束”的实现，显式处理原表已经超限；状态保持与恢复不混淆。
