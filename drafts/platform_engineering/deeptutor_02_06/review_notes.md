# 02.06 审阅记录：树与有序索引

DeepTutor BookEngine 的八节草稿已完成并通过 HTTP Markdown 导出核对。正式课程以草稿的教学问题为起点，按 Go 初学者的前置知识重新组织；本记录和 `original.md` 保留原始生成内容与修订依据。

## 教学结构

- 先用 IM 的消息 ID 点查与会话 seq 历史范围查询提出需求，再解释根、父子、叶、深度、高度和 BST 的左右不变量。
- 全章固定 `4,2,6,1,3,5,7` 这一组键推导查找、中序、闭区间 `[2,5]`；之后才用顺序插入 `1..7` 给出退化反例，避免多个图例来回切换。
- 分开讲内存 BST 的比较次数与数据库页树的页访问直觉；64 键、每叶 4 键、内部 4 路的三层树明确标为玩具模型。
- 结尾回到 `(conversation_id,seq)` 历史分页和 `message_id` 点查，以 22 道分层自检题让读者先回答再看反馈。

## 技术修订

- 草稿在树高的“节点数/边数”口径上不统一，并曾将顺序插入五节点链写成高度 n。正式页统一以**边数**计，单节点高度 0；七节点右链高度 6，示例平衡形状高度 2。
- 草稿在不同段落混用 4 路与 8 路的页树扇出，进而给同一数量级的键数不同层数。正式页只使用 64 键/4 键每叶/4 路内部页，计算 16 个叶页、4 个中间页、1 个根页，即三层。
- 中序范围 `[2,5]` 是升序闭区间推导；历史游标 `seq<5 ORDER BY seq DESC LIMIT 2` 是另一种降序分页访问，示例结果 `4,3`。两者的方向和边界分别说明。
- `seq` 明确是会话业务序号，避免草稿“传输序号”的说法与 TCP 序号混淆；多个会话可共享同一 seq，复合索引键必须带会话 ID。
- `O(h+k)` 解释边界定位加 k 条输出，普通 BST 退化到 `O(n)`；不会把有序范围查询笼统表述为永远 `O(log n)`。
- PostgreSQL 和 SQLite 官方资料只用于核对一般有序索引与页存储；没有推断实际数据库页容量、OpenIM 索引定义或查询计划。也没有声称页树的玩具图对应它们的物理布局。
