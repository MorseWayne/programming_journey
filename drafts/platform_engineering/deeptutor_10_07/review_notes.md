## 教学重组

- 先按独立业务规则写三类性质：解析接受值满足非空/最多 6 UTF-8 B 和可信身份；并发同 ID 最多一项受理、另一项 409；旧连接 gen41 不能覆盖新 gen42。
- Go `FuzzXxx(*testing.F)`、`f.Add` 种子和 `testdata/fuzz` 回归只用于输入边界；HTTP 拒绝时状态不变要在请求/存储层另外核对，不能只 fuzz 纯解码器。
- 两段分别加锁的 Check/Insert 可无 data race 但两个 goroutine 都先见缺，再各自派生 E9；短交错表与业务断言比“最终 map 一键”更能揭露重复效果。
- 连接状态机的 `OnClose(gen41)` 晚到只可清旧连接；目标围栏、本机 socket 已发字节与跨节点租约仍分开。

## 技术修订

- 原稿把 **4096 B** 写成“整个 HTTP 请求（请求行、首部、空行与正文）”上限；当前 09.02 合同限定的是**请求正文读取量**。正式页区分原始 HTTP 请求体 4096 B 与解码后消息正文 6 B。
- 原稿有模糊测试成功分支 `0 ≤ body ≤ 6B`，与当前正文**非空**要求矛盾。正式页在接受性质中固定 `1–6B`；纸上代码明确解析成功不等于业务 Validate 成功。
- 原稿把非法 UTF-8 作为 Go `encoding/json` 必然拒绝的输入；正式页只把它列为种子，要求按具体解析器与既定合同确定断言，不凭印象假设库行为。
- 原稿出现“不超过6字符”等易混用语。正式页始终按 UTF-8 **字节**判，`"你好"=6B`、`"你好呀"=9B` 只作为脱敏边界例子。
- 单进程 `-race` 只覆盖执行到的内存数据竞争；门闩/fake 只覆盖安排的交错；08.11 跨节点历史另要真实路由与调用/返回。五层证据矩阵避免一项绿冒充全系统正确。
- 固定 OpenIM 两段源码仅可作为只读实现路径证据，本章没有对其运行 Go 测试、fuzz 或故障注入。
