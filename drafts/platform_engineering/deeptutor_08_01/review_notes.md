# 08.01 审阅记录：系统模型与部分失败

## 教学重组

- 固定 A 在 t=0 发请求、t=100 ms 期限到达。R1 请求未达 G、R2 G 暂停尚未写 S、R3 S 在 t=20 已提交但答复丢失、R4 S 已提交后 G 崩溃；A 都只见超时。R2 仅在 t=100 未提交，不能推断以后不会提交。
- 先区分节点、链路、请求尝试和业务消息 ID，再讲 crash-stop、暂停、延迟、分区与局部故障。超时只给观察者有限证据，不能作为远端死亡证明。
- 安全性限于“同 ID 至多一条权威行”和受控授权等明确不变量；活性附权威恢复、网络连通、授权仍有效等前提。永久分区下不得承诺任意固定时限的结果。
- Go `context` 取消是协作信号，不撤销 S 已提交事务。超时后保留稳定 `m-9`，经授权查权威；既有 409 只说明 ID 占用，不证明同一意图已成功。

## 技术修订

- 原稿中一处把 **S2 200** 说成“权威存储已接受并持久化”、把 **S3 200** 说成“设备已确认接收”，与本项目固定合同完全相反。正式页全程保持 S2 `accepted_in_memory`，S3 v2 只为提议的 `stored_in_teaching_db`，设备结果另计。
- 原稿多处建议“同 ID 重试返回此前结果”，会暗改既有重复 ID 一律 409 的规则；正式页只给授权查询与冲突核对方案，更强幂等响应须另审版本化接口合同。
- 原稿把 R1 的请求未达 G 说成服务器可确认未写。正式页说明这是**纸上真相**，A 单凭同一个超时无法证明 R1，而 G/S 证据也需关联同一请求。
- 超时/取消、健康检查失败与分区都不是远端事务回滚或节点死亡证明。FLP 只作为特定完全异步共识问题的进阶限制，不用来宣称普通 IM 查询无法完成。
- 课程时间线 t=20/100/120 是单一纸上坐标，真实多机事件次序不能仅靠各自壁钟推断；实验需要受控门闩、权威状态与端到端关联 ID。
