## 本卷的定位与入口

先修：事务、网络与基本并发；先定义权威数据，再选择缓存或消息机制。

## 已完成的独立章稿

[07.01 访问模式与状态角色](./01_access_state_roles.md)以虚构 c-a 的历史、成员资格、预览、在线提示和计数为线索，先判断权威/派生/临时，再推导访问模式、命中/陈旧和缓存丢失后的恢复。[07.02 Redis 数据模型](./02_redis_data_model.md)再依访问形状比较 String、Hash、Set、ZSET、List、位图和 Stream 的边界。[07.03 缓存读取与更新](./03_cache_read_update.md)用 seq8→seq9 的两条交错推导旧值回填、负缓存与失效政策。[07.04 缓存过载与热点](./04_cache_overload_hotspots.md)用 c-g 同键失效、百键雪崩和随机无效 ID 算回源预算。[07.05 缓存服务的持久与故障](./05_cache_persistence_failure.md)按派生/临时/权威角色比较无持久、RDB、AOF、复制切换与冷启动。[07.06 消息抽象](./06_message_abstractions.md)用在线提示、后台索引和离线补拉比较队列、Pub/Sub 与可回放日志。[07.07 确认、重投与去重](./07_ack_retry_dedup.md)以 E9 的发布/消费 ACK 丢失、短去重窗口和编辑版本推导重复效果。[07.08 顺序与并发消费](./08_order_concurrent_consumption.md)用 E9/E10 同分区、F1 跨分区和批量/再平衡解释完成乱序。[07.09 积压与坏消息](./09_backlog_poison_messages.md)用 c-g 到达/完成速率与 E-bad/E11 队头阻塞评审重试、隔离和重放。[07.10 事务边界与 outbox](./10_transaction_outbox.md)以 m-9 和 E9 推演同库原子记录、转发故障、消费者幂等及外部效果。[07.11 派生视图与事件时间](./11_derived_views_event_time.md)用 E9/E10 的迟到与重放推导预览、搜索、统计窗口和权威重建。[07.12 跨系统数据一致性案例](./12_cross_system_consistency_case.md)把历史、搜索、预览、通知与离线补拉合成一条业务确认及修复链。十二章各八节、22 道分层练习均已完成。

## IM 主线中的位置

在线与会话缓存、消息转发、序号状态、队列确认、重复投递、热点群、积压追平与历史重建。

主参照与源码入口见 [OpenIM 阅读地图](../im_reference.md)。下方章号继续用于知识定位；已有正文中的旧业务例子作为补充，独立章稿生成时按本节主线适配。

## 本卷综合任务

对照 OpenIM 的转发与推送路径，为消息事实、在线通知和历史补拉分别定义状态与恢复，覆盖重复、积压和迟到消息。

任务由学习者在具备环境时执行。理论推导、参考示例、个人实现和真实运行记录分别保存，故障与反例属于必需部分。

## 达到的能力

能说清每份数据的角色、每种确认的意义、每种故障后的恢复来源。

用解释、最小实现、失败变式、业务取舍四类证据评审。只有目录、术语定义或参考代码通过，不能直接记为掌握本卷。

## 本卷章节展开规则

每章从一个明确问题开始，先补齐本章所需定义，再推导机制；至少含一条完整执行过程、一个反例、分层练习、反馈与业务迁移。复杂章节拆成多课，不把整卷知识压成一次速读。
