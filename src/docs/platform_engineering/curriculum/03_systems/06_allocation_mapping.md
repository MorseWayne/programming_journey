# 03.06 分配与映射：从 Go 对象到进程 RSS

> DeepTutor 初稿经技术与教学审阅后的静态课程。消息、缓冲、内存槽和时间线均为纸上模型；没有运行 Go、`mmap`、Linux 观测、IM 服务、基准或站点。这里讨论的 Go 运行时以官方 `gc` 工具链文档为依据，具体分配路径、指标和系统行为需在使用的版本与环境中核对。

## 一、一条消息结束后，内存到底经过了几道手？

假设虚构 IM 网关读取 `c-a` 的一页历史，暂时持有消息缓冲 B。请求结束后，业务代码不再需要 B，Linux 进程的 RSS 却没有立即下降。能否据此判定内存泄漏？03.05 已说明 RSS 是**驻留页**的统计视角，虚拟地址和已占物理页不是一回事。现在还需补上 Go 语言与运行时的几层责任。

先看对象的生命周期链：

```text
业务不再需要 B
  → 程序中是否仍有引用？
  → 若不可达，GC 何时识别并清扫？
  → Go 分配器是复用空位，还是获得一整块空闲页？
  → 运行时是否把空闲物理页归还给操作系统？
  → Linux RSS 在同一时刻如何统计？
```

每个箭头都是一个需要条件和证据的步骤。**“业务上结束”不保证 B 已不可达；“B 已不可达”不保证此刻已清扫；“已清扫”也不保证物理页立即归还。** 如果小切片仍指向大底层数组、队列仍保存引用，或者缓存有意保留历史，B 可能仍然可达；这些和分配器保留空页是不同原因。

## 二、Go 栈、Go 堆、进程内存：同一个词可能指不同东西

Go 函数和 goroutine 会使用**调用栈**保存执行状态，Go 运行时还管理可由垃圾回收器处理的**堆对象**。编译器决定一个值可否安全放在栈上，或其生命周期需要逃逸到 Go 堆。这里不应教成“局部变量必在栈，取地址就必在堆”：是否逃逸取决于它如何被使用，编译器分析会演进。Go 初学者先掌握**值能否在当前调用结束后继续被引用**，再查具体构建版本的逃逸结果。

Go 的 `[]byte` 是切片值，携带对底层数组的引用及长度、容量。例子：一个 64 KiB 底层数组装了历史消息，只保留 `preview := full[:8]` 的小视图；若 `preview` 仍被某处引用，底层数组也可能继续保持可达。把 `full` 设为空值只移除了**一个**引用，不能证明数组已经不可达：

```go
// 仅展示引用关系的片段；不是可独立运行的程序。
full := make([]byte, 64*1024)
preview := full[:8]              // 与 full 共用底层数组
full = nil                       // preview 仍可能保留整块底层数组
small := append([]byte(nil), preview...) // 独立复制前 8 字节
preview = nil                    // 还要检查是否存在别的引用
_ = small
```

若需求仅保留 8 字节预览，应明确制作独立的小副本并清除其他旧引用，随后还要等 GC 与分配器处理；这只是所有权设计，不保证 RSS 当场下降。上面代码也不声称具体变量一定逃逸或底层数组的物理页数。

还要区分三个容易混淆的“堆”：02.07 的**二叉堆**用于优先队列；Go **GC 堆**用于管理部分 Go 对象；操作系统/进程的内存映射视图还包括代码、栈、共享库、文件映射和运行时区域。名字相同或都在“进程内存”里，不表示可用同一个指标计数。

Go GC 沿根引用追踪对象：局部变量、全局变量以及其他可达对象上的引用都可能让某个缓冲保持可达。**可达不等于业务仍想用**，所以从业务上认为“已结束”却仍留在队列或全局缓存，正是需要检查引用关系的情形。反之，只有当对象不可达，GC 才有机会回收它占用的 Go 堆空间；GC 不管理所有进程内存来源，例如外部库单独管理的内存或内核 socket 资源。

## 三、分配器的空槽与页：用玩具模型理解“已空闲但未归还”

假设一个**纯教学**分配块占 4 KiB，被划成四个 1 KiB 槽，供同类对象复用。原有四个缓冲 A、B、C、D 各占一个槽；B、C、D 清扫后只有 A 仍活：

```text
4 KiB 玩具块：| A 活 | B 空 | C 空 | D 空 |
             1 KiB  1 KiB  1 KiB  1 KiB
```

空的 3 KiB 是此块容量的 **75%**，可交给后续同类分配；但这个块还有 A，不能把**整块**直接当作完全空闲的 4 KiB 页面归还。这个图解释的是“对象回收”与“整块可归还”之间的差别，不声称 Go 真用 1 KiB 槽或每个这样的块恰好等于一个 OS 页。Go 的真实大小类别、span、页面粒度与清扫器机制复杂，需按版本核对。

两类空隙要分开：对象占用的槽大小可能大于对象实际字节，产生**内部空隙**；分配块中只有零散空槽，导致整块不能释放，是**部分占用造成的保留**。即使有可复用的空槽，后续不同大小的对象也未必正好使用它。反过来，不连续的**物理**页框通常可以映到连续的虚拟地址，不能把“物理不相邻”直接说成 Go 大对象必然分配失败。

官方 `runtime.MemStats` 中，`HeapInuse−HeapAlloc` 可作为已经给大小类别使用、但当前未装入对象的空间的一个**上界估计**；不是“所有浪费字节”的精确值。`HeapIdle−HeapReleased` 则估计空闲 span 中仍由运行时保留、可能归还操作系统的量。两者都要放到**版本、时间点与对象分布**下解释，不能看一个差值就诊断泄漏。

## 四、t0–t3 时间线：引用断开不等于 RSS 同步下降

固定两个相互独立的纸上缓冲 A、B，每个业务内容恰为 4 KiB。这里不宣称它们恰好一页一个对象；Go 分配器还有对象头、大小类别、对齐和其他开销。A 仍被使用，B 原先由一个临时任务持有。

| 时刻 | 业务与引用状态 | Go 堆层面 | 操作系统层面 |
|---|---|---|---|
| t0 | A、B 均可达 | 两个对象仍被分配 | 对应页可能已驻留 |
| t1 | B 的**最后一个**引用断开 | B 已不可达，但尚可能计入 `HeapAlloc` | RSS 没有必须立即变化的理由 |
| t2 | 某轮 GC 标记与清扫完成 | B 占用的 Go 堆空间可复用，`HeapAlloc` 可能下降 | 所在分配块仍可被运行时保留，RSS 可不变 |
| t3 | 分配块有条件成为空闲并被归还 | `HeapReleased` 可能增加，或空闲空间先被复用 | RSS 可能随后变化；也有别的进程内存来源在变化 |

这里 t1 的“最后一个引用断开”是**假设**，不是从请求返回自动推出。如果一个长寿命 `map`、队列或小切片仍引用 B，t1 根本没有发生：GC 正确地保留了 B。若 t2 后 `HeapAlloc` 下降而 RSS 不下降，先看复用与页归还；若 `HeapAlloc` 在同口径稳定流量下持续增长，再审阅可达引用、队列积压和缓存上限。两个现象的调查路径不同。

`TotalAlloc` 是 Go 堆对象分配字节的**累计量**，正常运行中不会因 GC 而回落；用它的持续增长证明泄漏是误读。`HeapAlloc` 包含可达对象，也可能含已不可达但尚未清扫的对象，所以一次快照不能直接等同“当前业务确实还需的字节”。

## 五、`mmap`：让文件或匿名来源进入进程地址视图

`mmap` 是一种建立虚拟地址映射的接口。**匿名映射**没有普通文件作为内容来源，可服务于进程内存分配；**文件映射**把文件内容对应到虚拟地址范围，访问时由内核处理页的载入。它不是 Go 切片语法，也不是“写入消息必然落盘”的保证；实际 Go 运行时如何取得与归还内存由其实现决定。

按 Linux `mmap(2)` 的两种文件映射语义看一个只读聊天日志的纸上需求：

| 模式 | 对映射写入的可见性 | 持久性提醒 |
|---|---|---|
| `MAP_PRIVATE` | 私有写时复制，修改不向其他映射者传播，也不写回原文件 | 不能把私有修改当作日志更新 |
| `MAP_SHARED` | 共享映射中的修改可对其他映射者可见 | “别人看得到”仍不等于已按崩溃要求落盘；同步与耐久在 03.08 学 |

若教学程序只读，映射权限也应按只读需要设置；“文件映射”本身不自动给写权限。Linux 文档还说明，建立映射后**关闭原文件描述符不会撤销映射**；撤销映射是另一个生命周期操作。要管理映射，就要同时想清文件对象、地址范围、权限和关闭/解除映射的时机。越界访问或源文件变化的错误路径也需要专门设计，这里只建立入口。

为避免混淆：Go 业务消息的 `[]byte`、系统匿名映射和映射日志文件，可能最终都使进程某些页驻留，但**所有权与释放机制不同**。Go GC 不会因为某个普通文件映射页暂时不再被业务引用就自动替应用关闭任意手工建立的外部映射。03.08 会说明 `write`、同步调用和崩溃后的数据保证；本章不作“已持久化”结论。

## 六、页缓存与 RSS：文件数据可能在两个视角出现

Linux **页缓存**保存最近使用的文件内容，让之后的普通读写或映射访问有机会复用页面。一次普通 `read` 可令文件页进入内核页缓存，同时把结果复制到进程自己的缓冲；**未映射到该进程地址空间的页缓存**不必出现在该进程 RSS 中。若进程将文件 `mmap` 并触碰了映射页，驻留的文件页又可能计入它的 `RssFile`。这是同一类文件数据在“系统缓存”与“某进程驻留映射”中的不同观察角度，不能一律相加当作两份独立物理页。

因此，“节点可用内存下降，而网关 `RssAnon` 基本不变”可能与日志或历史文件的页缓存有关，但仍需同时间窗的系统/容器内存与文件 I/O 证据，不能凭一个曲线定因。反过来，进程 RSS 上升也可能是映射文件页被触碰，不一定是 Go 堆对象增加。

`/proc/<pid>/status` 的 `VmRSS` 是进程驻留集的快速统计，分成匿名、文件和共享内存等视角；文档提示部分值不精确。`/proc/<pid>/smaps` 可给每个映射提供 `Rss` 与按共享比例分摊的 `Pss` 等更细信息，但读取和解释成本更高。多个进程的 RSS 相加会把共同映射的物理页重复计入；需要估计分摊时再看 PSS。**指标的单位、时间和统计范围**必须一起记录，单个“内存使用”数字不足以定位消息缓冲。

## 七、Go 与 Linux 指标对账：先问谁在计数

下面只说明官方指标的含义，不拿其中任何一个直接当真实网关的泄漏判据：

| 指标 | 主要计什么 | 不能直接代表什么 |
|---|---|---|
| `HeapAlloc` | 已分配的 Go 堆对象字节，含尚未清扫的不可达对象 | 全进程 RSS、全部业务有用对象 |
| `TotalAlloc` | 启动以来累计的 Go 堆对象分配字节 | 当前存活量 |
| `HeapSys` | Go 堆保留的**虚拟地址空间** | 已驻留物理内存 |
| `HeapIdle−HeapReleased` | 空闲 span 中仍保留、可用于估计潜在可归还量 | 必然会立刻归还的内存 |
| `HeapReleased` | Go 堆中已向操作系统归还的物理内存量 | 全进程释放量或 RSS 下降量 |
| `VmRSS` | Linux 进程驻留页的快速统计 | 仅 Go 堆或进程独占页 |
| `RssAnon/RssFile/RssShmem` | 匿名、文件映射和共享内存的驻留分类 | 业务对象归属和精确逐对象账本 |

Go 的 `GOMEMLIMIT` 是**Go 运行时管理内存的软限制**，官方说明其范围不含二进制映射、其他语言自行管理的内存和操作系统代表程序持有的资源；它不能直接替代容器/进程硬限制，也不能承诺 RSS 永不越过某个数。对 IM 网关，内核 socket 缓冲、文件页缓存、TLS 或外部库内存可能落在不同统计范围，真正的容量判定要等 03.10/03.11 的观测与限制模型。

面对“关闭历史查询后 RSS 不降”，先按**同一请求负载和时间窗**提出可检验的分叉：A）引用仍在队列/缓存？B）`HeapAlloc` 已降但 `HeapIdle−HeapReleased` 较大？C）`RssFile` 随文件映射而变？D）Go 指标稳定但进程/容器内存继续增长？这只是调查顺序，不是从一个快照就能执行的自动诊断。后续真实实验还需记录版本、输入和基线，区分因果与同现。

## 八、交付内存责任图与分层练习

交付四张纸：画 `preview` 与完整底层数组的引用图；列出 t0–t3 各层可说与不可说的结论；画四槽玩具块并标出可复用空槽与无法整块归还的原因；最后用指标表为“RSS 不降”提出至少两种相互竞争的解释和所需证据。纸上推导不等于在真实 Linux/Go 版本观察到相同数值。

### 分层练习：先答，再展开反馈

<details><summary>1. 业务代码不再需要 B，就证明 B 已不可达吗？</summary>

不能。其他切片、队列、缓存或全局变量仍可能引用它。</details>

<details><summary>2. 局部变量一定在 goroutine 栈上吗？</summary>

不一定；具体位置取决于编译器按使用情境做的逃逸分析。</details>

<details><summary>3. 对局部变量取地址就一定分配到 Go 堆吗？</summary>

不一定；要看地址是否逃出可安全管理的生命周期。</details>

<details><summary>4. 保留 8 字节的小切片能使 64 KiB 底层数组继续可达吗？</summary>

可能。切片值仍引用底层数组，须检查其他引用与复制策略。</details>

<details><summary>5. 把 `full` 设为空值就断开所有引用了吗？</summary>

没有，只断开这一个变量持有的引用。</details>

<details><summary>6. 02.07 的二叉堆与本章 Go GC 堆是同一种结构吗？</summary>

不是。前者按优先级选元素，后者是运行时管理某些 Go 对象的内存区域。</details>

<details><summary>7. 玩具 4 KiB 块有一个活槽、三个空槽，可以立刻归还整块吗？</summary>

不能按这个玩具规则整块归还；活槽 A 仍需该块。空槽可先用于复用。</details>

<details><summary>8. 玩具块的 1 KiB 槽就是 Go 真实大小类别吗？</summary>

不是，它只演示部分占用与整块归还的差别。</details>

<details><summary>9. 物理页框不连续，就必然无法得到连续虚拟缓冲吗？</summary>

不是。页表可把不连续物理页框映到连续虚拟页。</details>

<details><summary>10. t1 时 B 的最后引用断开，`HeapAlloc` 必须立即下降吗？</summary>

不必；不可达对象可能尚未被 GC 清扫。</details>

<details><summary>11. t2 清扫后 B 的空间可复用，RSS 必须马上下降吗？</summary>

不必；运行时可能保留分配块供后续使用，且 RSS 还有别的来源。</details>

<details><summary>12. `TotalAlloc` 不下降能证明泄漏吗？</summary>

不能。它是累计分配量，正常运行也会增长。</details>

<details><summary>13. `HeapAlloc` 精确等于当前业务有用的对象大小吗？</summary>

不等于；它还可能包含尚未清扫的不可达对象，且不涵盖进程所有内存。</details>

<details><summary>14. `HeapSys` 与进程 RSS 是同一统计口径吗？</summary>

不是。`HeapSys` 是 Go 堆保留的虚拟空间，RSS 是进程驻留页。</details>

<details><summary>15. `HeapReleased` 增加是否必然让同一瞬间的 RSS 等量下降？</summary>

不能这么推断；RSS 含其他来源、共享页和采样时差。</details>

<details><summary>16. `MAP_PRIVATE` 修改会写回原文件吗？</summary>

不会按该映射语义写回；它是私有写时复制。</details>

<details><summary>17. `MAP_SHARED` 中的修改对别人可见就证明已耐久吗？</summary>

不能。可见性与崩溃后的持久性是不同合同。</details>

<details><summary>18. 建立 `mmap` 后关闭文件描述符会自动解除映射吗？</summary>

不会。映射有自己的生命周期，需另行解除。</details>

<details><summary>19. 普通 `read` 产生的文件页缓存必然计入该进程 RSS 吗？</summary>

不必；未映射的内核页缓存与进程驻留映射是不同视角。</details>

<details><summary>20. 映射文件被触碰后的驻留页可能进入哪个 RSS 分类？</summary>

可进入 `RssFile`；仍须按具体映射和统计口径核对。</details>

<details><summary>21. 多进程 RSS 相加为何可能高估独占内存？</summary>

共享映射的同一物理页可分别计入多个进程的 RSS；PSS 是另一种分摊视角。</details>

<details><summary>22. `GOMEMLIMIT` 能保证整个容器 RSS 绝不超限吗？</summary>

不能。它是 Go 运行时管理内存的软限制，不覆盖全部外部和内核内存。</details>

- [Linux 内核：Page Cache](https://www.kernel.org/doc/html/latest/mm/page_cache.html)与[OSTEP：Memory API](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-api.pdf)：文件缓存与分配层次；OSTEP 的 `malloc/free` 例子属于 C，不是 Go 的对象释放接口。

按[学习路线](../learning_path.md)，下一章[03.07 文件与目录](./07_files_directories.md)进入文件名、inode、描述符和打开文件的生命周期，为日志轮转与 03.08 持久化建立前置。离开本章前，应能解释**一个引用为何让大底层数组保留、GC 回收与页归还为何分时发生、映射/页缓存为何不能简单算作 Go 堆，以及哪种指标能检验自己的假设**。
