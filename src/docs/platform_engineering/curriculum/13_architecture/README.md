## 已完成的独立章稿

[13.01 问题定义与利益相关者](./01_problem_stakeholders.md)已完成。它用虚构的 A 发送、B 离线 25 小时后补历史需求，拆分用户旅程、确认点、目标/约束/假设、六段质量属性场景与证据缺口。[13.02 领域与状态建模](./02_domain_state_modeling.md)继续区分用户/设备/会话/消息、请求与意图 ID、权威序号、事件和连续游标。[13.03 模块与信息隐藏](./03_modules_information_hiding.md)比较泄漏式与语义型 Go 接口，按可能变化的决定评审包和确认边界。[13.04 架构风格与边界](./04_architecture_styles_boundaries.md)沿 A→权威→E9→B 对照单体、事件和独立服务的事务及故障代价。[13.05 容量与数据设计](./05_capacity_data_design.md)按连接、权威历史、事件和设备任务四本账推增长、热键与积压恢复。[13.06 质量属性的冲突](./06_quality_attribute_tradeoffs.md)以 DB 故障、长离线、非成员和热群场景评审速度、持久、安全与成本。[13.07 设计说明与评审](./07_design_review_adr.md)把目标、候选、故障、容量、验证与 proposed ADR 连成可反驳的纸上方案。[13.08 迁移与兼容](./08_migration_compatibility.md)用扩展/迁移/收缩阶段审唯一权威、影读对账、旧端和新数据回退责任。[13.09 跨团队交付](./09_cross_team_delivery.md)把产品、客户端、Go、数据、安全和值班的契约、依赖与用户验收合在一张交付板。九章各含 8 节讲解、22 道分层练习；13.10–13.12 仍按下方设计展开。

## IM 主线中的位置

比较单聊、小群、大群、客服与协作场景；讨论消息保证、扩散策略、存储、兼容、成本和迁移。

主参照与源码入口见 [OpenIM 阅读地图](../im_reference.md)。下方章号继续用于知识定位；已有正文中的旧业务例子作为补充，独立章稿生成时按本节主线适配。

## 本卷综合任务

完成一份 IM 设计、验证、迁移、发布和接手说明，并针对群规模、离线时长、旧客户端或恢复目标变化进行答辩。

任务由学习者在具备环境时执行。理论推导、参考示例、个人实现和真实运行记录分别保存，故障与反例属于必需部分。

## 达到的能力

高级能力以可重复的判断、交付和协作为证据，不以读完目录或记住术语认定。

用解释、最小实现、失败变式、业务取舍四类证据评审。只有目录、术语定义或参考代码通过，不能直接记为掌握本卷。

## 本卷章节展开规则

每章从一个明确问题开始，先补齐本章所需定义，再推导机制；至少含一条完整执行过程、一个反例、分层练习、反馈与业务迁移。复杂章节拆成多课，不把整卷知识压成一次速读。
