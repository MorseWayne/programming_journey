## 一、从任务积分认识值、变量与类型

### 1.1 同样显示为 20，程序理解的内容可能不同

程序处理的是有类型的值。**值**是某个具体数据；**类型**规定这类数据能够表示什么、可以参加哪些操作。先认识三种：

| 源码中的写法 | 含义 | 适合表达的业务信息 |
|---|---|---|
| `20` | 整数数值 | 积分、数量 |
| `"20"` | 字符串，也就是一段文本 | 原始输入、展示文字、编号 |
| `true` | 布尔值，表示真 | 任务是否完成 |

`bool` 是布尔类型的名字，只有 `true` 和 `false` 两种值。`string` 是字符串类型的名字。`int` 是本章首先使用的整数类型，取值范围将在第三节解释。

**变量**可以先理解为“程序中带名字的存放位置”。名字让代码找到它，类型约束它能保存什么，值是它当前保存的内容。下面是完整程序：

```go
package main

import "fmt"

func main() {
	var score int = 20
	var label string = "20"
	var finished bool = true

	fmt.Println(score)
	fmt.Println(label)
	fmt.Println(finished)
}
```

预期依次输出 `20`、`20`、`true`，各占一行。前两行外观相同，不代表两个值具有相同类型。数值 `20 + 5` 得到 `25`，文本 `"20" + "5"` 得到拼接后的 `"205"`。

逐项读第一条声明：`var` 表示声明变量；`score` 是名字；`int` 是类型；`=` 后的 `20` 是初始值。声明建立了这个变量，后面的打印只是读取它。

### 1.2 声明一次，可以修改多次

**赋值**表示将右侧的值写入左侧已有变量。它使用 `=`。完整程序：

```go
package main

import "fmt"

func main() {
	var score int
	fmt.Println(score)

	score = 20
	fmt.Println(score)

	score = score + 5
	fmt.Println(score)
}
```

按顺序追踪，而不是把最后一行当作数学方程：

| 执行到哪里 | 发生什么 | `score` 当前值 |
|---|---|---:|
| `var score int` | 声明整数变量，得到默认初值 | 0 |
| 第一次打印 | 读取当前值 | 0 |
| `score = 20` | 将 20 写入变量 | 20 |
| 第二次打印 | 读取当前值 | 20 |
| `score = score + 5` | 先读取旧值 20，算出 25，再写回 | 25 |
| 第三次打印 | 读取当前值 | 25 |

因此预期输出为 `0`、`20`、`25`。变量没有自动保留每次更新的历史；如果业务将来要求解释每笔积分变化，还需要另外设计记录。

这里默认得到的 `0` 只是语言规定的初值。它是否表示“已确认零分”，必须由业务规则决定，不能从这条声明本身推断。

### 1.3 显式类型、类型推断与短声明

下面四种写法都能建立一个初值为 20 的 `int` 变量，**选择其中一种使用**：

| 写法 | 类型从哪里来 | 当前怎样使用 |
|---|---|---|
| `var score int = 20` | 明确写出 `int` | 初学时便于逐项阅读 |
| `var score = 20` | 根据初始值推断为 `int` | 省略能够推断的类型 |
| `score := 20` | 根据初始值推断为 `int` | 函数内常见的短声明 |
| `var score int`，随后 `score = 20` | 声明时明确写出 `int` | 先有默认值，再赋值 |

**类型推断**是编译器在声明时确定类型。类型不会因为后续赋值自动改成别的类型；值可以改变，变量的静态类型保持不变。

故意错误片段，放在 `main` 内观察：

```go
score := 20
score := 25 // 错误：同一块内没有新变量
fmt.Println(score)
```

第二行应改为 `score = 25`。再把第二行改为 `score = "25"` 仍然错误，因为已经确定为 `int` 的变量不能直接接收 `string`。

`:=` 只能出现在函数内部。同一代码块中，一次短声明可以包含多个名字，但必须至少声明一个新变量；本章后面接收两个解析结果时会用到它。当前先掌握单个名字的规则：**新建用声明，更新用赋值。**

**停下来预测：** 从 `points := 10` 开始，依次执行 `points = points + 7`、`points = points - 2`，最后是什么？应为 15。能够说出中间值 17，比只猜到最终结果更有用。

## 二、零值、常量、作用域与表达式

### 2.1 零值是语言初值，缺失是业务状态

声明变量而没有给初始值时，Go 会提供该类型的**零值**。本章的基本类型如下：

| 类型 | 零值 | 不能自动得出的业务结论 |
|---|---|---|
| `int` | `0` | 用户已经确认获得零分 |
| `string` | `""`，长度为零的文本 | 用户已经填写姓名 |
| `bool` | `false` | 已经检查过任务且确认未完成 |

例如运营录入奖励时，“尚未填写”和“明确填写 0 分”可能是两种状态。只保存一个整数会让这两者都落在 `0` 上。先用两个变量表达，片段放在 `main` 中并导入 `fmt`：

```go
var reward int
var filled bool
fmt.Println(reward, filled) // 预期：0 false

reward = 0
filled = true
fmt.Println(reward, filled) // 预期：0 true
```

逗号把传给 `fmt.Println` 的两个值分开，它会在输出之间加入空格。两次积分数值相同，但第二个变量记录了是否填写。现在先理解这种明确记录状态的方法，后面再学习怎样把相关字段组织成一个整体。

不要随意选择 `-1` 表示缺失。若需求以后允许扣分，这个约定会与合法数据冲突。确实要采用特殊值时，需要明确它永远不属于合法值域，并让每个使用者遵守相同约定。

### 2.2 表达式先得到结果，赋值再改变状态

**表达式**是能够求得一个值的写法，例如 `35`、`score`、`score + reward`。算术运算符 `+`、`-`、`*`、`/`、`%` 分别表示加、减、乘、除和取余数。完整程序：

```go
package main

import "fmt"

func main() {
	score := 120
	reward := 35
	cost := 18

	score = score + reward
	score = score - cost

	doubleReward := reward * 2
	average := score / 2
	remainder := score % 2

	fmt.Println(score)        // 预期：137
	fmt.Println(doubleReward) // 预期：70
	fmt.Println(average)      // 预期：68
	fmt.Println(remainder)    // 预期：1
}
```

计算顺序是 `120 → 155 → 137`。整数除法的结果向零截断：`137 / 2` 为 68，`-137 / 2` 为 -68。这里“向零”意味着去掉小数部分，不能理解为总向更小的整数取整。

余数帮助解释没有分完的部分：`137 = 68 × 2 + 1`。因此，把 137 分平均分给两人，若规则只允许整数分，每人 68 分后还剩 1 分；怎样处理剩余部分是业务规则，程序不会替你决定。

乘除取余的优先级高于加减，`10 + 2 * 3` 为 16，`(10 + 2) * 3` 为 36。圆括号表达你希望先完成的计算。不要为了缩短代码而把重要业务步骤全部塞进一行。

`=` 是赋值；`==` 才是相等比较，结果为布尔值。`fmt.Println(score == 137)` 预期打印 `true`。整数除数为零也不合法：常量表达式中的零除会在编译时被拒绝；整数变量在运行时除以零会触发运行时错误。第三节说的“溢出不自动报错”，不能推广到所有算术错误。

### 2.3 常量描述编译时就能确定的值

**常量**由 `const` 声明，值在编译期确定，之后不能重新赋值。它适合表达固定数值或文本，例如本次程序约定的积分上限。

片段放在 `main` 中并导入 `fmt`：

```go
const startingPoints = 100
score := startingPoints + 20
fmt.Println(score) // 预期：120
// startingPoints = 200 // 故意错误：常量不能重新赋值
```

常量不是“目前没打算修改的变量”。从外部输入读取、运行后才知道的值，不能直接拿来作为常量声明的值。是否长期保持不变，与是否在编译期可确定，是不同的问题。

**第二遍阅读：未定类型常量。** `const count = 3` 没有指定具体整数类型，可以在能够表示 3 的多个类型中使用。`int64` 是另一种整数类型，它的固定范围在下一节介绍。

```go
const count = 3
var small int = count
var large int64 = count
fmt.Println(small, large) // 预期：3 3
```

上面是 `main` 内片段，需要 `fmt`。对照下面的故意错误片段：

```go
count := 3                 // 变量的类型已经推断为 int
var large int64 = count    // 错误：不能直接把 int 变量赋给 int64
fmt.Println(large)
```

变量类型不同，需要显式转换，后面会讲 `int64(count)`。常量也不能任意塞进任何类型：`const rate = 0.5` 可以作为浮点数使用，却不能直接赋给 `int`，因为整数类型不能表示半个单位。

### 2.4 作用域回答“这个名字在这里指向谁”

花括号 `{` 和 `}` 可以围成一个**代码块**。**作用域**描述某个声明的名字在源码的哪些位置可见。对于本章的局部变量，声明语句结束之后，在所在代码块内可以使用它；嵌套块通常也能看到外层名字。

完整程序：

```go
package main

import "fmt"

func main() {
	score := 80
	{
		bonus := 20
		fmt.Println(score, bonus) // 预期：80 20
	}
	fmt.Println(score) // 预期：80
	// fmt.Println(bonus) // 故意错误：这里看不到 bonus
}
```

内层块的 `bonus` 不能在外层使用。取消最后一行的注释会得到编译错误，不会得到一个新零值。这里说明的是名字可见范围，不能据此断言某块内存会在闭花括号处立即释放；内存生命周期将在相应章节解释。

如果内层声明同名变量，会发生**遮蔽**：在内层范围内，名字指向新变量。下面是另一个独立的 `main` 内片段，需要 `fmt`：

```go
score := 10
{
	score := 99
	fmt.Println(score) // 预期：99
}
fmt.Println(score) // 预期：10
```

把内层 `score := 99` 改为 `score = 99`，两次输出都会变成 99。前者建立新变量，后者修改可见的外层变量。这也是为什么排查“明明更新了，外面还是旧值”时，要仔细看 `:=` 与 `=`。

**本节检查：** 能否分别解释“默认值为什么是 0”“为什么 0 不等于未填写”“为什么内层同名变量不会自动修改外层变量”？若只能记住输出，回到状态表重新追踪声明和赋值。

## 三、整数的范围与越界发生的位置

### 3.1 从两个开关推导有限范围

计算机使用二进制位保存信息。一个**位**（bit）有 0 和 1 两种状态，8 位组成 1 **字节**（byte）。先只用 2 位：

| 编码 | 按无符号整数解释 |
|---|---:|
| `00` | 0 |
| `01` | 1 |
| `10` | 2 |
| `11` | 3 |

每位有两种选择，两位共有 `2 × 2 = 4` 种组合。一般地，n 位有 `2ⁿ` 种组合；8 位就是 `2⁸ = 256` 种。若全部用于非负整数，从 0 开始，最后一个数是 255，而不是 256。

**无符号整数**使用全部编码表示非负值；**有符号整数**把一部分编码用于负值。Go 的 `uint8` 和 `int8` 都有 8 位，但解释方式不同：

| 类型 | 范围 | 本章用途 |
|---|---|---|
| `uint8` | 0 到 255 | 观察无符号范围 |
| `int8` | -128 到 127 | 用容易观察的小范围演示越界 |
| `int32` | -2147483648 到 2147483647 | 明确 32 位有符号边界 |
| `int64` | -9223372036854775808 到 9223372036854775807 | 需要固定较大整数范围时考虑 |
| `int` | 32 位或 64 位，由目标平台决定 | 本章小规模计数和积分计算 |

不要求背出大整数边界。要记住三件事：位数有限、符号影响解释、`int` 不保证总是 64 位；`int` 与 `int32` 也不是同一种类型。

### 3.2 常量无法表示：编译阶段就会拒绝

下面是故意错误片段：

```go
var x int8 = 128
fmt.Println(x)
```

128 是源码中已知的常量，超过 `int8` 最大值 127。编译器可以直接判定无法表示，因此程序不能开始运行。`var x uint8 = -1` 和 `var x uint8 = 256` 也属于这一类。

这不是“运行后自动改成别的值”。错误发生在哪个阶段，决定你应当去查看编译诊断，还是追踪运行过程。

### 3.3 已有变量运算越界：程序可能继续执行

完整程序：

```go
package main

import "fmt"

func main() {
	var x int8 = 127
	x = x + 1
	fmt.Println(x)
}
```

这里声明的初值合法，加法使用的是 `int8` 变量。结果超过该类型能表示的上界，发生**溢出**。预期输出 `-128`。Go 的整数溢出本身不会自动触发运行时恐慌（`panic`），有符号溢出结果由该类型的表示规则确定。

因此“程序没有报错”不能证明积分计算正确。业务希望 127 加 1 得到 128，而类型只能保存另一种结果；这需要在选择类型和执行运算前处理。

**第二遍阅读：补码如何解释这个结果。** 8 位无符号编码从右到左的权重是 1、2、4、8、16、32、64、128。Go 有符号整数采用二进制补码；解释为 `int8` 时，最高位的权重为 **-128**，其余各位权重保持为正。它不是“一个符号位加七位绝对值”。

`01111111` 表示 `64 + 32 + 16 + 8 + 4 + 2 + 1 = 127`；加 1 后成为 `10000000`，按补码解释为 -128。n 位有符号整数的最小值是“2 的 n−1 次方取负”，最大值是“2 的 n−1 次方减 1”；代入 n = 8，就得到 -128 和 127。

同样，`uint8` 的 255 加 1 会回到 0。学习时可以分别预测 `int8` 初值为 126、127、-128 时加 1 的结果：127、-128、-127；只有第二种越过了上界。

### 3.4 窄化转换不负责确认业务合法性

**显式转换**写作 `目标类型(值)`，例如 `int64(count)`。把较宽整数转为较窄整数称为窄化，可能丢失高位信息。以下片段放在 `main` 中并导入 `fmt`：

```go
var total int64 = 300
var small int8 = int8(total)
fmt.Println(small) // 预期：44
```

300 无法放入 `int8`。转换保留低 8 位，300 减去 256 得到 44，对应剩下的编码。这不是范围校验，也不表示 300 与 44 在业务上等价。把 `total` 改为 128，结果会是 -128。

对照：`int8(300)` 直接转换常量，会在编译阶段因无法表示而报错；上面转换已经有类型的变量，则允许执行。判断某个例子前，先看它处理的是常量还是变量。

对于任务积分，类型选择至少回答：是否允许负数？最大累计量是多少？是否需要跨平台保持同一范围？计算中间值是否可能更大？选择 `int64` 能扩大范围，但不能让整数无限增长。第七节将用明确业务上限说明怎样在相加前检查。

**反例练习：** 产品规定积分永不为负，是否改用无符号类型就能避免错误扣分？不能。无符号减法也可能越界，例如 `uint8` 的 0 减 1 会得到 255。业务规则需要显式检查。

## 四、浮点近似、显示格式与业务单位

### 4.1 能写小数，不代表能精确保存所有小数

有些数据需要小数，例如完成比例、测量值或平均耗时。`float64` 是 Go 常用的浮点类型，以固定的 64 位保存数值表示，因此精度和范围都有边界。“浮点”可以先理解为与科学计数法类似，用有效数字和指数表示不同大小的数。

二进制小数点后各位的权重依次是 `1/2`、`1/4`、`1/8`……。十进制 0.5 等于 `1/2`，所以二进制 `0.1` 就能表示；十进制 0.1 的二进制表示则是无限循环的 `0.0001100110011…`，有限位数无法完整保存。

这与十进制写 `1/3 = 0.333…` 类似：一旦只能保留有限位数，就需要取一个近似值。`a := 0.1` 创建的是 `float64` 变量，它保存的不是数学意义上精确的十分之一。0.5 则可以精确表示，因此“所有小数都不精确”也不正确。

### 4.2 先认识格式化输出，再观察误差

`fmt.Println` 适合直接显示值。`fmt.Printf` 接收一个格式模板，将后面的值按占位符输出；它不会自动在末尾换行。本章用到的符号如下：

| 模板符号 | 作用 |
|---|---|
| `%d` | 十进制整数 |
| `%t` | 布尔值 `true` 或 `false` |
| `%g` | 浮点的一般格式，默认使用足以识别该值的最少数字 |
| `%.17g` | 浮点的一般格式，最多 17 位有效数字 |
| `%f` | 固定小数格式，默认小数点后 6 位 |
| `%.2f` | 固定小数格式，小数点后 2 位 |
| `\n` | 字符串中的换行转义，让下一次输出从新行开始 |

有效数字与小数点后位数不同：`%.17g` 中的 17 约束有效数字，不表示固定保留 17 位小数。下面是完整程序：

```go
package main

import "fmt"

func main() {
	a := 0.1
	b := 0.2

	fmt.Printf("a = %.17g\n", a)
	fmt.Printf("b = %.17g\n", b)
	fmt.Printf("a+b = %.17g\n", a+b)
	fmt.Printf("a+b == 0.3: %t\n", a+b == 0.3)
	fmt.Printf("0.1+0.2 == 0.3: %t\n", 0.1+0.2 == 0.3)
}
```

这一具体例子的预期输出是：

```text
a = 0.10000000000000001
b = 0.20000000000000001
a+b = 0.30000000000000004
a+b == 0.3: false
0.1+0.2 == 0.3: true
```

`a`、`b` 在声明时都推断为 `float64`。它们各自先保存近似值，变量加法再产生一个可表示的结果。比较 `a+b == 0.3` 时，右侧常量按左侧的浮点类型参与比较；两个浮点值不相同，因此为 `false`。

最后一行全部由未定类型常量组成，按精确常量计算规则，0.1 加 0.2 等于 0.3，因此为 `true`。**不要把常量表达式与已有浮点变量的计算混为一谈。** 源码看起来相似，计算规则却有区别。

### 4.3 改变显示方式，没有改变保存的数值

独立片段，放在 `main` 内并导入 `fmt`：

```go
a := 0.1
b := 0.2
fmt.Printf("a 的短格式：%g\n", a)
fmt.Printf("a 的细节：%.17g\n", a)
fmt.Printf("和的短格式：%g\n", a+b)
fmt.Printf("和的固定格式：%f\n", a+b)
fmt.Printf("和的两位小数：%.2f\n", a+b)
```

预期输出：

```text
a 的短格式：0.1
a 的细节：0.10000000000000001
和的短格式：0.30000000000000004
和的固定格式：0.300000
和的两位小数：0.30
```

`%g` 不保证把这个和显示为 `0.3`；其默认规则要能够区分不同的浮点值。`%f` 和 `%.2f` 则按规定的小数位数格式化显示。打印 `0.30` 没有把原变量修改成精确的 0.3，也不会让前面的相等比较变为真。

同理，多打印几位只是帮助观察，不会增加计算精度。这些字符串也不一定是内部二进制值的完整十进制展开。

**预测再尝试：** 把变量改为 `a := 0.5`、`b := 0.25`，比较 `a+b == 0.75`。预期为 `true`，因为这些二进制分数及其结果都能精确表示。不能从某一个失败比较推断所有浮点相等比较都错误。

### 4.4 用需求决定单位、舍入和比较规则

Arena 的本章规则只允许整数积分，所以用整数表达更直接。在可表示范围内，整数加减能精确保留每一分。若未来允许半分，可以考虑改为“每单位代表半分”的整数表示，但字段含义、输入和展示都必须一起定义。

另一个教学例子：若价格最小单位明确是分，可以保存 1999 分来表达 19.99 元。片段放在 `main` 中并导入 `fmt`：

```go
var priceCent int64 = 1999
var count int64 = 3
totalCent := priceCent * count
fmt.Println(totalCent) // 预期：5997，即 59.97 元
```

整数最小单位避免了这次计算中的小数近似，却没有自动解决所有问题：订单数量可能导致乘法越界，折扣可能产生不足一分的结果，不同输入可能使用不同单位。需要先确定最大值、舍入时机、舍入方向和单位转换规则。

浮点数仍适合许多测量、统计和近似计算。若需求是“误差在允许范围内”，就应说明误差如何定义、允许范围来自哪里；不能把某个固定小量套到所有尺度和所有业务中。当前先学会问：这次比较要判断的是精确计数、显示结果，还是可接受的近似？

## 五、布尔条件、最小分支与文本

### 5.1 把业务要求翻译成真假问题

布尔值回答“是否成立”。整数比较的结果也是布尔值。片段放在 `main` 内并导入 `fmt`：

```go
score := 78
fmt.Println(score == 78) // 预期：true，等于
fmt.Println(score != 60) // 预期：true，不等于
fmt.Println(score > 60)  // 预期：true，大于
fmt.Println(score >= 78) // 预期：true，大于或等于
fmt.Println(score < 100) // 预期：true，小于
fmt.Println(score <= 78) // 预期：true，小于或等于
```

多个要求可以组合：`&&` 表示并且，两边都真才真；`||` 表示或者，至少一边真就真；`!` 表示取反。

| 左边 | 右边 | 左边 `&&` 右边 | 左边 `\|\|` 右边 |
|---|---|---|---|
| `true` | `true` | `true` | `true` |
| `true` | `false` | `false` | `true` |
| `false` | `true` | `false` | `true` |
| `false` | `false` | `false` | `false` |

积分在 0 到 100 之间，应写 `score >= 0 && score <= 100`。低于 0 或高于 100 时应拒绝，可写 `score < 0 || score > 100`。如果把合法条件误写为 `score >= 0 || score <= 100`，连 120 都会通过，因为左侧已经成立。

Go 不会把整数或字符串自动当作真假。0 仍是整数，`""` 仍是字符串；要判断零或空文本，需要写出 `score == 0`、`text == ""`，它们才产生布尔结果。

### 5.2 第一次使用 if：条件决定执行哪一块

`if` 表示“如果”，后面跟布尔条件和花括号；条件为真时执行块内语句。`else` 表示“否则”，在条件为假时执行另一个块。完整程序：

```go
package main

import "fmt"

func main() {
	score := 78
	valid := score >= 0 && score <= 100

	if valid {
		fmt.Println("积分在允许范围内")
	} else {
		fmt.Println("积分超出允许范围")
	}
}
```

这里 `valid` 保存一个 `bool`。当前它为 `true`，所以只输出“积分在允许范围内”。改成 `score := 120` 后走 `else`，两个分支不会在一次判断中都执行。

`if` 的条件不要求额外圆括号；需要分组时仍然可以写圆括号。花括号不能因为块内只有一句就省略。本例将 `} else {` 写在同一行，按这个格式书写即可。故意错误的 `if score { ... }` 或 `if "通过" { ... }` 不能编译，因为条件类型不对。

本章只使用最小分支完成数据校验。更多分支组合、循环和把规则抽成函数，将在 01.03 系统展开。

### 5.3 短路：有些右侧表达式不会执行

对于 `A && B`，若 A 已为假，整体必为假，B 不再求值；对于 `A || B`，若 A 已为真，B 不再求值。这叫**短路**，不只是“最后结果一样”。

片段放在 `main` 中并导入 `fmt`：

```go
divisor := 0
canDivideEvenly := divisor != 0 && 10%divisor == 0
fmt.Println(canDivideEvenly) // 预期：false
```

左侧 `divisor != 0` 为假，右侧取余不会执行，因此没有发生除以零。把两侧交换顺序，就会先计算 `10%divisor` 并触发运行时错误。条件的顺序在这里承担了检查责任，不能随意互换。

### 5.4 字符串边界要看清

双引号表示字符串字面量，引号本身不属于保存的文本。需要在文本中表示换行、双引号或反斜杠时，用转义：`\n`、`\"`、`\\`。

完整程序：

```go
package main

import "fmt"

func main() {
	message := "积分已更新"
	raw := " 25\n"
	fmt.Println(message)
	fmt.Printf("原始文本：%q\n", raw)
	fmt.Println("她说：\"积分正确\"")
	fmt.Println("目录是 C:\\score")
}
```

`%q` 为字符串输出带双引号和必要转义的形式，便于看清边界。上例第二行预期显示 `原始文本：" 25\n"`，其中可以看见开头的空格和结尾的换行转义。普通打印时，这些差异很容易被忽略。

字符串之间的 `+` 用于拼接，例如 `"积分：" + "25"` 得到 `"积分：25"`。字符串与整数不能直接相加；`"积分：" + 25` 是类型错误。可以先用 `fmt.Printf("积分：%d\n", 25)` 输出，整数转文本的函数则在下一节介绍。

### 5.5 len 数的是字节，不是看到的字数

Go 的 `string` 保存不可变的字节序列。本章直接写入的中文源码字面量采用 UTF-8 编码；字符串本身也可以保存不是合法 UTF-8 的字节，因此不能把字符串类型等同于“必定合法的 Unicode 文本”。

**编码**是把文字映射为数字和字节的规则。Unicode 给文字等元素分配码点；UTF-8 用一个或多个字节表示这些码点。当前先看一组确定的例子，片段放在 `main` 中并导入 `fmt`：

```go
fmt.Println(len("Go"))       // 预期：2
fmt.Println(len("Ada"))      // 预期：3
fmt.Println(len("积分"))     // 预期：6
fmt.Println(len("分数: 90")) // 预期：10
```

`len` 是 Go 内置的取长度操作。这里“积”和“分”各占 3 个 UTF-8 字节，所以 `len("积分")` 为 6。“分数: 90”包含两个各占 3 字节的汉字，再加冒号、空格和两个数字，共 10 字节。这些是具体字面量的确定结果。

`byte` 是 `uint8` 的别名，表示一个字节；`rune` 是 `int32` 的别名，通常用来表示 Unicode 码点。一个人眼看到的字符有时由多个码点组成，因此 rune 数量也不总等于视觉字符数。

如果需求是“字段最多 20 字节”，`len` 很合适；如果是“昵称最多 20 个可见字符”，就要先定义字符计数方式。字符串遍历、UTF-8、码点与安全切分会在 01.04 详细讲解。现在不要用 `len(text) == 2` 判断“恰好两个汉字”。

## 六、类型转换与文本解析：失败也是结果

### 6.1 先分清已经有数值，还是只有文本

**数值转换**处理已经具有数值类型的值，例如 `int64(count)`；**解析**检查一段文本是否符合数字写法，并尝试取得它表达的数值，例如将 `"25"` 解析为整数 25。

| 当前有什么 | 希望得到什么 | 使用方式 | 要关心的问题 |
|---|---|---|---|
| `int` 变量 | `int64` 数值 | `int64(n)` | 数值类型是否匹配、范围是否足够 |
| `float64` 变量 | `int` 数值 | `int(x)` | 小数被截掉、范围是否有效 |
| 十进制文本 | `int` 数值 | `strconv.Atoi(text)` | 语法或范围可能失败 |
| `int` 数值 | 十进制文本 | `strconv.Itoa(n)` | 后续使用文本还是数值 |

`strconv` 是 Go 标准库中的字符串转换包，需要像 `fmt` 一样导入。`Atoi` 与 `Itoa` 是它提供的函数名字，大小写要保持一致；函数接收输入并给出结果的完整模型将在下一章展开。

故意错误写法 `int("25")` 不能完成文本解析。另一个易错写法 `string(65)` 虽然允许，却得到 Unicode 码点 65 对应的 `"A"`，并不是十进制文本 `"65"`。整数格式化为十进制文本应使用 `strconv.Itoa(65)`。

### 6.2 浮点变量转整数会向零截断

完整程序：

```go
package main

import "fmt"

func main() {
	positive := 8.9
	negative := -8.9
	fmt.Println(int(positive)) // 预期：8
	fmt.Println(int(negative)) // 预期：-8
}
```

这里转换已保存为 `float64` 的变量，向零截断小数部分。它既不是四舍五入，也不是一律向下取整：-8.9 向下取整为 -9，向零截断则为 -8。

这一说明以截断后的值处于目标整数范围内为前提。超范围浮点转换不能当作有效的范围检查，也不能依赖它来修复错误输入。

对照故意错误片段：

```go
fmt.Println(int(3.9)) // 错误：常量 3.9 不能表示为 int
```

不要因为变量转换能截断，就把常量转换也写成同样结论。将它改为 `value := 3.9`，再调用 `int(value)`，才是本节讨论的变量转换；预期得到 3。这个区别与第三节的“常量越界”和“变量窄化”相呼应。

### 6.3 两个返回值：一个结果，一个错误信息

先读这条语句：

```go
number, err := strconv.Atoi(text)
```

它调用 `strconv.Atoi`，将 `text` 中的十进制整数文本尝试解析为 `int`，并接收两个结果：`number` 是数值结果，`err` 是错误信息。逗号把接收结果的变量名分开，`:=` 声明这两个变量。

本章对 `error` 只引入必要用法：它是用来表达失败的类型；对这里的 `err`，`nil` 表示没有错误，`err != nil` 表示发生了错误。`nil` 不是数字 0，也不是空字符串；现在不需要先学习接口就能使用这个检查方式，错误类型的机制会在后续章节深化。

完整程序：

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	text := "42"
	number, err := strconv.Atoi(text)

	if err != nil {
		fmt.Printf("输入无效：%q\n", text)
	} else {
		fmt.Printf("解析结果：%d\n", number)
	}
}
```

`import` 后的圆括号把多个包放在一个导入组里。这里预期输出 `解析结果：42`。改成 `text := "4.2"` 后，预期输出 `输入无效："4.2"`；因为本例要解析整数，带小数点的文本不符合它的语法。

下面每行输入应单独替换，再预测路径：

| 文本 | Atoi 是否成功 | 本章如何理解 |
|---|---|---|
| `"25"` | 成功，25 | 合法整数文本 |
| `"-7"` | 成功，-7 | 负号是合法语法；业务是否允许另行检查 |
| `"0"` | 成功，0 | 明确提供了零 |
| `""` | 失败 | 空文本没有提供整数 |
| `"25分"` | 失败 | 带有非整数后缀 |
| `"25.0"` | 失败 | 这不是整数文本写法 |
| `" 25"` | 失败 | Atoi 不会自动去掉前导空格 |
| `"999999999999999999999999999999"` | 失败 | 超出 32 位和 64 位 int 范围 |

应否容忍空格、是否允许单位后缀，都要由输入协议决定。如果需要清理输入，要明确讲解清理规则；不要让读者误以为解析函数会自动替自己处理所有格式。

### 6.4 先处理 err，再使用 number

解析失败有不同原因。`strconv` 用语法错误和范围错误区分部分情况；遇到范围错误时，返回的数值不一定是 0。因此不能通过“解析结果等于零”判断失败，也不能在错误时继续拿结果更新积分。

上一完整程序把使用 `number` 的代码放在 `else` 中，保证只有无错误路径能够到达它。另一个常用写法是失败后提前结束，以下是 `main` 内片段，需要导入 `fmt` 和 `strconv`：

```go
text := "25分"
number, err := strconv.Atoi(text)
if err != nil {
	fmt.Println("输入不是有效整数")
	return
}
fmt.Println(number)
```

`return` 表示结束当前函数。在这里当前函数是 `main`，因此后面的打印不会执行。若没有 `return`，仅打印一条错误提示，程序仍会继续往下走；那就没有阻止错误结果被使用。

只允许本章这个无后台任务的小程序直接返回即可。更大程序怎样分类错误、选择退出码、记录日志、释放资源，需要在掌握函数和资源管理后继续设计。

**第二遍阅读：固定解析位宽。** `Atoi` 的结果是平台对应的 `int`。如果数据契约规定为 64 位十进制整数，可以进一步阅读 `strconv.ParseInt(text, 10, 64)`：10 指定进制，64 指定有符号位宽，返回 `int64` 与错误。它仍然需要先检查错误，再做业务范围校验。

### 6.5 把整数变回文本用于展示

独立片段，放在 `main` 中并导入 `fmt`、`strconv`：

```go
points := 65
text := strconv.Itoa(points)
message := "当前积分：" + text
fmt.Println(message) // 预期：当前积分：65
```

这里 `points` 仍为 `int`，`text` 和 `message` 为 `string`；函数返回文本，没有改变原变量的类型。之后若要继续加分，仍应使用数值变量 `points`。反复把数值转成文本再解析回来，会增加混淆和出错的机会。

至此可以看见三个独立问题：类型是否能表示这个数，文本是否能解析为这个数，业务是否允许这个数。`"-7"` 可以成功解析为整数，但本章的奖励规则仍可以拒绝它。

## 七、完整积分更新、分层练习与验收

### 7.1 先写规则，再写程序

将需求收窄为一次奖励录入，便于把基础知识连起来：

1. 已有积分必须处于 0 到 1000 分之间。
2. 奖励以十进制整数文本提供；空文本、非法文本和超出 int 范围的文本均拒绝。
3. 奖励不得为负；本题允许奖励为 0，表示合法的无变化操作。
4. 更新后不得超过 1000 分。
5. 任一检查失败，本次不能修改已有积分。

这些是当前练习的业务约定。现实需求如果允许扣分、小数积分或不同账户上限，需要重新确定值域和检查规则。本章先把一组约定解释完整。

可以用一句话描述更新前后都应成立的条件：**积分始终位于 0 到 1000 之间。** 这类必须保持的条件称为不变量。我们会靠检查顺序维护它。

### 7.2 完整程序

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	const limit = 1000
	balance := 120
	raw := "25"

	delta, err := strconv.Atoi(raw)
	if err != nil {
		fmt.Println("拒绝：增量不是有效整数")
		return
	}

	if balance < 0 || balance > limit {
		fmt.Println("拒绝：已有积分不合法")
		return
	}

	if delta < 0 || delta > limit-balance {
		fmt.Println("拒绝：增量超出允许范围")
		return
	}

	before := balance
	balance = balance + delta
	fmt.Printf("更新成功：%d -> %d\n", before, balance)
}
```

这一输入的预期输出为 `更新成功：120 -> 145`。`before` 保存更新前的值，用来对照打印；它没有建立永久历史记录。程序没有接入文件或数据库，退出后这些局部变量中的状态不会自动持久保存。

### 7.3 为什么检查必须放在这些位置

| 阶段 | 此时已知什么 | 接下来允许做什么 |
|---|---|---|
| 设置初始值 | 上限 1000，已有值 120，文本为 `"25"` | 尝试解析文本 |
| 检查 `err` 后 | 解析成功，delta 为 25 | 按整数讨论增量 |
| 检查 balance 后 | `0 <= balance <= 1000` | 安全计算剩余额度 `limit-balance` |
| 检查 delta 后 | `0 <= delta <= limit-balance` | 安全计算新积分 |
| 执行赋值后 | balance 为 145 | 输出更新前后的值 |

已有积分检查不能因为初始例子恰好是 120 就省略。练习换成负数或过大值时，仍应先拒绝。确认 balance 在范围内后，剩余额度一定在 0 到 1000 之间，减法不会越界。

接着比较 `delta > limit-balance`，在相加前就能判断是否超过额度。只有通过检查才执行加法，此时结果必在 0 到 1000 内；这个范围在 Go 的 32 位和 64 位 `int` 中都能表示。

常见反例是先写 `next := balance + delta`，再判断 `next > limit`。如果未经检查的 delta 很大，加法可能已经溢出；此时再比较变形后的结果，不能补救之前失去的信息。我们的顺序避免了这一步。

错误路径中的 `return` 保证不会落到最后的赋值。程序的结构因此与“失败时不改变积分”这条规则直接对应，而不是仅仅在屏幕打印了一条拒绝信息。

### 7.4 用边界用例验证自己是否理解规则

每次只改表中指定的输入，其余保持一致。以下是推导的预期，实际运行结果请记录在自己的学习笔记中：

| balance | raw | 预期路径 | 执行后原积分是否改变 |
|---:|---|---|---|
| 120 | `"25"` | 更新成功，得到 145 | 改为 145 |
| 120 | `"0"` | 更新成功，得到 120 | 数值保持 120 |
| 120 | `""` | 解析失败 | 保持 120 |
| 120 | `"25分"` | 解析失败 | 保持 120 |
| 120 | `"25.0"` | 解析失败 | 保持 120 |
| 120 | `"-1"` | 能解析，但增量范围不合法 | 保持 120 |
| 120 | `"880"` | 恰好到达上限 1000 | 改为 1000 |
| 120 | `"881"` | 超过剩余额度 880 | 保持 120 |
| 980 | `"30"` | 超过剩余额度 20 | 保持 980 |
| 1001 | `"1"` | 已有积分不合法 | 保持原值 1001，拒绝本次操作 |
| -1 | `"1"` | 已有积分不合法 | 保持原值 -1，拒绝本次操作 |
| 120 | `"999999999999999999999999999999"` | 解析范围错误 | 保持 120 |

输入原本就违反不变量时，程序报告并拒绝，不能声称已修复原状态。真实系统还需要决定谁负责调查和修正已有错误数据；本章先把拒绝路径表达清楚。

### 7.5 分层练习：先作答，再看反馈

每道题先写预测与理由，再修改自己的代码。故意错误片段单独使用，不能混入完整更新程序。

#### 起步层：读懂并预测

**练习 1：声明与赋值。** 在同一块中依次写 `points := 10`、`points := 20`、`fmt.Println(points)`，能否打印 20？怎样只改一个符号使它符合“修改已有积分”的要求？

<details>
<summary>提示与反馈</summary>

检查第二条语句有没有新变量。这里没有，程序不能通过编译。将第二行的 `:=` 改为 `=` 后，预期打印 20。解释应包含“同一块”和“已有变量”，而不只说某个符号总不能重复。

</details>

**练习 2：零与缺失。** `var reward int` 得到 0，是否能证明运营填写了 0？用本章已学类型分别表达“未填写”“已填写零分”“已填写 10 分”。

<details>
<summary>提示与反馈</summary>

增加 `filled` 布尔变量。三种状态可表示为 `(reward=0, filled=false)`、`(reward=0, filled=true)`、`(reward=10, filled=true)`。整数的零值只说明变量初值，是否填写需要明确记录。还要约定未填写时不把 reward 当作已确认数据使用。

</details>

**练习 3：算术与范围。** 从 50 分开始，奖励 17 分，消耗 9 分；最后按每组 3 分分组，有几组、余几分？再分别判断：常量 128 赋给 int8、int8 变量 127 加 1、int64 变量 300 转成 int8。

<details>
<summary>提示与反馈</summary>

最终 58 分，整数商 19、余数 1。后三项依次是编译错误、运行时溢出为 -128、窄化转换为 44。不能统一回答“都会报错”，也不能统一回答“都会变负数”；错误阶段与具体值都需要说明。

</details>

#### 原理层：构造一个能区分规则的反例

**练习 4：常量与浮点变量。** 为什么 `0.1+0.2 == 0.3` 为真，而 `a := 0.1`、`b := 0.2` 后的 `a+b == 0.3` 为假？把和用 `%.2f` 打印后再比较，会改变布尔结果吗？

<details>
<summary>提示与反馈</summary>

前者按未定类型常量的精确规则计算，后者使用已表示为 float64 的变量。`%.2f` 只改变输出文本，不改变变量。只回答“计算机有误差”不够，还需要说明近似从何时开始，以及为何两个写法遵循不同规则。

</details>

**练习 5：类型转换还是解析。** 对比 `int(3.9)`、先声明 `x := 3.9` 再调用 `int(x)`、`strconv.Atoi("3.9")`。它们能否取得整数 3？再解释如何把整数 65 变成文本 `"65"`。

<details>
<summary>提示与反馈</summary>

第一项不能编译，常量不能表示为 int；第二项是变量转换，向零截断得到 3；第三项返回解析错误，因为文本不是整数写法。整数格式化用 `strconv.Itoa(65)`，不能用会得到 `"A"` 的 `string(65)`。三个相似写法应按不同规则分别判断。

</details>

**练习 6：文本与条件。** 判断 `len("积分") == 2` 是否为真；如果字段只允许 0 到 100，为什么 `score >= 0 || score <= 100` 不合适？各给一个具体反例。

<details>
<summary>提示与反馈</summary>

第一项为假，len 计算 UTF-8 字节数，这段文本长度为 6。范围条件应使用 `&&`；score 为 120 时，错误条件的左侧为真，因此整体为真。对于下界，还可以用 -1 检查错误条件的右侧。分别测试上下边界，能避免只验证一个方向。

</details>

#### 实践层：自己改变输入和规则

**练习 7：拒绝必须阻止赋值。** 将综合程序输入改成 `"25分"`，再尝试删除解析错误分支里的 `return`。只看到拒绝提示，是否足以证明没有更新？怎样从后续执行路径判断？

<details>
<summary>提示与反馈</summary>

原程序解析失败后结束 main，最后的赋值不可到达。删除 return 后，程序会继续执行后续逻辑，错误结果可能被使用。不能依赖此次失败恰好返回哪个数值来证明正确；应恢复提前返回，或将成功处理放入 else。验收要同时检查是否打印了拒绝、是否还能走到更新语句。

</details>

**练习 8：修改业务规则。** 将上限改为 500，本次要求奖励必须大于 0。独立修改检查，并列出“零奖励、恰好到上限、超过上限、非法已有积分”四类输入。

<details>
<summary>提示与反馈</summary>

将常量 limit 改为 500，将 `delta < 0` 改为 `delta <= 0`。例如 balance=120 时，raw 为 `"0"` 应拒绝，`"380"` 成功到 500，`"381"` 拒绝；balance=501、raw=`"1"` 应在已有积分检查处拒绝。只改常量不够，因为零奖励规则也变了。

</details>

#### 业务迁移层：解释方案的适用范围

**练习 9：从积分迁移到库存。** 假设仓库已有 120 件货，本次入库数量来自文本，容量为 1000。哪些规则可以复用？若改成“出库”，能否只把加号换成减号？

<details>
<summary>提示与反馈</summary>

整数单位、文本解析、先检查旧状态、失败不修改、容量检查的思路都可复用；字段和提示语应反映库存含义。出库要重新规定数量是否允许为零，并在相减前检查出库量非负且不超过已有库存。直接换减号会保留错误的检查条件。这里只讨论一次本地计算，多人同时操作、持久保存和重复请求需要后续机制。

</details>
