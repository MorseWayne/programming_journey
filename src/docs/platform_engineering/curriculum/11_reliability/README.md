## 已完成的独立章稿

[11.01 业务结果与测量](./01_business_measurement.md)已完成。它承接 09.01–09.04 的消息确认点、03.04 的 CPU 等待和 04.01 的时延分层，用虚构同一队列样本讲事件、单位、时间窗、分母、重试和资源观察。[11.02 分布与统计](./02_distributions_statistics.md)继续用十项手算时延讲均值、分位数、直方图、样本量和错误聚合。[11.03 日志、指标与 Trace](./03_logs_metrics_traces.md)再沿同一 POST 设计三类互补证据及标签/采样边界。[11.04 诊断方法](./04_diagnostic_method.md)用五秒突发画像与 USE/黄金信号训练反证。[11.05 CPU 与内存性能](./05_cpu_memory_performance.md)用分配速率、存活堆和配额证据检查 Go 成本。[11.06 I/O 与网络性能](./06_io_network_performance.md)把低 CPU 的投递迟到拆成池、盘、网络和设备阶段。[11.07 压测与容量](./07_load_testing_capacity.md)用开闭环、遗漏、阶梯和 N−1 约束实验推论。[11.08 SLO 与告警](./08_slo_alerting.md)将用户确认点转成预算与行动门。八章各 8 节、22 道练习；11.09–11.12 仍按下方设计展开。

主参照与源码入口见 [OpenIM 阅读地图](../im_reference.md)。下方章号继续用于知识定位；已有正文中的旧业务例子作为补充，独立章稿生成时按本节主线适配。

## 本卷综合任务

从一个 IM 用户症状追踪到资源、存储或投递瓶颈，给出修复、恢复和复盘证据，所有数字标明条件与来源。

任务由学习者在具备环境时执行。理论推导、参考示例、个人实现和真实运行记录分别保存，故障与反例属于必需部分。

## 达到的能力

能用证据定位复杂问题，并把诊断、运行目标和团队行动连接起来。

用解释、最小实现、失败变式、业务取舍四类证据评审。只有目录、术语定义或参考代码通过，不能直接记为掌握本卷。

## 本卷章节展开规则

每章从一个明确问题开始，先补齐本章所需定义，再推导机制；至少含一条完整执行过程、一个反例、分层练习、反馈与业务迁移。复杂章节拆成多课，不把整卷知识压成一次速读。
