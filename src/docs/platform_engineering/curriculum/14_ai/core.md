## 一个答案“像真的”并不够

资料助手找到相关段落并生成流畅回答，仍可能遗漏条件、引用旧版本或执行了未经授权的动作。要判断失败来自哪里，需要理解模型、检索、执行与评测的不同角色。

先修：[D01 Python](../../13_python.md)、[D02 检索基础](../../14_rag.md)、[应用边界](../09_backend_security/core.md)。数学从向量与条件概率的最小模型补起。

## 一、向量如何表达相似

向量是一组有顺序的数字。点积是对应分量相乘再求和；几何长度由分量平方和开平方得到。余弦相似度比较方向，先要求能够处理非零长度。

`(1,0)` 与 `(0.8,0.6)` 的几何长度都是 1，点积为 0.8，因此余弦为 0.8。这只是一个计算关系，并不意味着文本有 80% 概率正确。

embedding 用模型把文本表示为向量。相似性反映模型训练形成的关系，可能帮助找到不同措辞的材料，但无法独立证明事实、权限或证据完整性。

## 二、条件概率解释生成的不确定性

以自回归文本生成模型为例，它依据已有上下文为下一个 token 给出概率分布，再按某种策略选择输出。token 是模型的文本单位，不一定对应完整词或一个汉字。

`P(下一项 | 已有上下文)` 中竖线表示“在给定条件下”。一段输出由连续多步组成，每一步都依赖此前的输入与生成结果。

训练改变参数，让模型在相应数据和目标上调整预测；推理使用当前参数处理新输入。把文档放进上下文通常没有重新训练模型，却会改变这次预测的条件。

这也解释了为什么同一问题在不同材料、提示或采样设置下可能给出不同结果。

## 三、注意力怎样联系上下文位置

可以先把注意力理解为：当前位置根据 query 与各位置的 key 计算关联，再把相应 value 按权重组合。具体实现还包含多头、层、位置与其他变换，不能用一句“查找相关词”代替全部机制。

教学例中两个 value 为 `(2,0)` 与 `(0,4)`，若权重为 0.75 与 0.25，加权结果为 `(1.5,1)`。这个例子帮助理解组合，不代表某个真实模型的推理内容。

较长上下文会增加相应计算与状态需求。生成服务还可区分处理输入的阶段和逐步输出的阶段；缓存已有计算结果能减少部分重复工作，但仍有内存与生命周期成本。

## 四、检索链路决定模型能看见什么

文档准备包括清洗、切分、版本、来源与权限。查询阶段可能先做词项或向量召回，再重排和组合上下文。

每一步都有独立失败：需要的文档不在索引中、分块丢失前提、相关片段排名太低、旧版本未过滤，或模型拿到正确材料后仍误述。

```text
原始资料 → 可追溯片段 → 授权范围 → 候选检索
  → 重排与选择 → 生成上下文 → 断言与引用核对
```

一次排序命中不能替后面的完整性与忠实性检查。若问题需要两个条件，只有其中一个条件的文档仍不足以回答。

## 五、用指标区分召回与噪声

一个问题有四份相关资料，前 3 条结果为 a、x、b，其中 a/b 相关、x 无关。该查询 hit@3 为命中，precision@3 为 2/3，recall@3 为 2/4。

这些指标描述不同目标。hit 很高可能仍漏掉关键材料；召回提升又可能带来更多噪声与上下文成本。多查询聚合时还需说明分母与方式。

回答还应检查每条断言的支持关系、问题覆盖与引用准确。模型裁判可以提供辅助，但其偏差与一致性也需要检查。

## 六、数据集决定评测的可信范围

把调试时反复使用的八条题全答对，不能说明对新问题同样有效。应保留独立样本，覆盖同义表达、缺条件、冲突、过期和权限不同的情形。

训练或调整过程中看到验证答案，会产生信息泄漏，使结果偏乐观。文档、标签、提示、模型和实现都应有版本，才能复核变化。

没有观察到失败不等于失败概率为零。样本少、任务单一或用户分布不同，都应限制结论范围。

## 七、工具执行必须继承后端保证

模型建议调用创建工单，不表示它拥有实际权限。执行层要确认可信主体、允许工具、参数、预算和需要的批准。

操作 ID 应稳定，效果端支持相应幂等或查询。checkpoint 只记录流程走到哪里，无法独立解决“工具已成功、流程未保存”的窗口。

提示注入的核心风险之一，是把待处理材料当成有权改变系统规则的指令。资料可以提供信息，但权限应由独立执行边界决定。

## 八、优化需要比较整个任务

更便宜的单次模型调用可能产生更多重试或工具步骤，使成功任务成本反而上升。更快的检索也可能减少证据，降低最终成功率。

同时记录质量、端到端延迟、拒答、权限与效果、模型和工具调用成本。缓存、批量、路由与微调各解决不同问题，应由失败分析决定选择。

微调适合改变某些行为或领域适应，但不自动取代持续更新的资料检索。是否训练需要数据、目标、预算与独立验证，不应因为工具可用就默认增加这一层。

## 九、从原型到持续交付

先建立确定性检索基线与固定样本，再加入真实生成并保存原始输出；之后增加受控工具，验证恢复；最后考虑灰度、反馈和版本回滚。

回滚不仅是换回模型名，还可能涉及提示、索引、资料版本与工具策略。已经发生的外部效果仍需业务处理。

### 分层练习

1. 手算两个向量的相似度，并说明它不能表达什么。
2. 为一个问题列出完整证据需求，再区分检索与生成失败。
3. 构造独立查询集，分别统计命中、拒答与断言支持。
4. 安排工具提交后、流程保存前的失败，说明恢复依据。
5. 比较两种优化方案的成功任务成本，而不只比较单次调用价格。
