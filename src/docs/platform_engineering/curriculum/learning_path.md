## 主线与当前入口

本系列围绕一个虚构的教学 IM 展开，主参照为 **OpenIM**。项目选择、固定版本、已核对源码与教学边界见[IM 主项目](./im_reference.md)。组织、用户、群组和消息均为虚构数据。

14 卷提供完整的语言与计算机知识体系；实际按 S0–S7 跨卷递进。每个阶段依次经历“IM 需求 → 基础理论 → 小模型与练习 → 源码对照 → 失败变式与取舍”。只在相关前置已经讲清时深入上游代码。

当前已完成 15 章：01.01–01.09、02.01–02.02、03.01、10.01–10.03。前两章原案例作为基础补充，其余按 IM 主线展开；正文与设计的区别见[编写与能力验收](./assessment.md)。14 卷全部 168 个单元已有具体 IM 练习与验收目标，长篇继续按先修关系完成。

## S0：认识一条消息，写清一条规则

**入口：** 从文件、目录、终端、保存、编译与运行开始，不预设 Go 经验。

**学习顺序：** [01 卷](./01_go/README.md)01.01 → 01.02 → 01.03 起步；穿插 [10 卷](./10_engineering/README.md)10.01 的需求边界、10.03 的差异与本地版本记录。

把最初需求限定为“输出一条文本消息，再判断本题允许的输入”：文本是什么类型？长度按字节还是文字计算？用户 ID 能否当作可计算整数？输入为空和明确提供零有何差别？本阶段只保存、计算和判断这些值。

条件、循环和普通函数先学；能够追踪调用后再学递归，理解作用域后再学函数值与闭包。先写出合法、空值、超限和非法格式的预测结果，再逐条核对。

**验收：** 独立修改一条校验规则，解释每个变量和返回结果。此时不预设消息已发送到网络，也不引入顺序保证、幂等和离线恢复。

## S1：从消息列表到本地会话工具

**入口：** 能读写普通函数、循环和失败分支。

**学习顺序：** 01.04 数组/切片/文本 → 01.05 map/结构体/指针 → 01.06 方法/接口 → 01.07 错误与资源 → 01.08 本地格式与 I/O → 01.09 包 → 10.02 测试 → 01.12 CLI。

先定义消息与会话：会话表示一组交流对象及其历史归属，消息包含本题需要的发送者、内容和标识。用切片保存列表，用 map 按会话查找；用复制与共享示例解释修改会影响谁。接口先用两种内存存储练习，学完文件后再加文件实现。

[02 卷](./02_algorithms/README.md)02.01–02.05 随这些操作讲解集合、计数、规模、对数、查找、哈希与排序。消息按什么键排列，要明确规则；不能仅凭本地时间戳就预先承诺全局顺序。

**P1 增量：** 一条消息 → 多条消息 → 会话索引 → 本地保存与导入 → 去重练习与测试。10.04–10.06 用该工具讲测试替身、重构和评审。此处去重只是有明确输入范围的本地规则，网络重试会在 S5 深化。

**验收：** 能改变文件格式或校验规则，解释非法输入和部分读写的处理；能说明正常保存与崩溃耐久性的区别。01.10 泛型、01.11 反射在 S4 后深化；网络标准库在 S2 补学。

## S2：连接两个客户端，理解一条网络消息

**入口：** 完成 P1，理解函数、接口、字节、错误与资源关闭。

**学习顺序：** [03 卷](./03_systems/README.md)03.01–03.04 的进程、线程与阻塞 → [04 卷](./04_networks/README.md)04.01–04.03 的通信、地址、HTTP 与 WebSocket 入门 → [05 卷](./05_runtime/README.md)05.01–05.03 的并发、同步与取消 → `net/http` 等网络标准库和 [09 卷](./09_backend_security/README.md)09.01–09.04。

先做只读历史查询，再做两个测试客户端之间的文本转发。解释 HTTP 请求与持久双向连接、消息边界、读写任务、关闭责任、连接失效和心跳。共享连接表或会话数据之前，必须先学同步和数据归属。

源码对照从 OpenIM 的 msggateway 进入，先看连接与消息入口。网关后的 RPC 和队列先标注职责，等到 S5 再追踪整条路径。

同阶段加入 09.08 的输入大小与日志边界、[11 卷](./11_reliability/README.md)11.01–11.03 的计数、耗时和错误分类，以及 10.09 的最小持续集成。

**P2 内存版验收：** 正常通信、非法载荷、连接关闭和慢接收方的基本行为可解释。明确进程退出会丢失哪些内存状态；在线转发成功不能自动代表离线用户也能恢复消息。

## S3：保存消息，建立身份与会话权限

**入口：** 理解网络处理、context、基本同步与 P2 的当前可靠性边界。

**学习顺序：**

1. [06 卷](./06_databases/README.md)06.01–06.03 先讲关系模型、基本 SQL 与数据身份，以会话成员和消息记录构造教学表。
2. 06.10 先讲查询、参数、结果与关闭责任；06.07 学事务语义，再回到事务 API 和 09.05 数据访问。
3. 补齐文档、集合、MongoDB 基本读写、索引和 Go 驱动，再对照 OpenIM 的实际存储路径。SQL 教学实现与上游实现明确标注。
4. 04.04–04.07 补传输、连接、流控与 TLS；09.06–09.08 学身份、凭据、会话成员权限、浏览器与输入输出边界。
5. 09.11–09.12 组织接口、安全负例与完整服务，11.08 起步部分明确历史查询和发送接口的服务目标。

**P2 持久版：** 登录后查询允许访问的会话，提交消息、查询历史并分页。先验证发送者身份和群成员权限，再讨论状态修改；不信任客户端自行填写的发送者身份。

历史保存、消息可见范围、群成员变更与消息发送之间的规则必须明确定义。进入源码前先解释关系与文档两种数据模型，不因选择 OpenIM 就跳过数据库理论。

**验收：** 解释越权读取、退群后发送、非法消息、重复提交和存储失败。此阶段明确教学实现的提交点；OpenIM 异步路径的受理、存储和推送关系将在 S5 核对。

## S4：分析慢客户端、大群与资源开销

**入口：** 已有带身份和持久历史的基本服务。

**学习顺序：**

1. 02.06–02.08 的树、堆、图；03.05–03.10 的虚拟内存、分配、文件、持久化、I/O 与诊断。
2. 05.04–05.07 的内存模型、调度、对象生命周期和 GC。
3. 06.04–06.06 的存储页、索引与执行，06.08–06.09 的并发控制和恢复；结合 MongoDB 的具体表示与操作范围对照。
4. 04.08–04.12 的网络 I/O、代理、RPC、网络层与排障。
5. 05.08–05.12、10.07–10.08、11.04–11.07 的受限并发、验证、分析工具、负载与容量。

用 IM 症状驱动理论：一个设备很慢，是否拖住整个群？群成员从 10 人变成 10000 人，扇出工作和缓存怎样变化？为什么连接数增长后内存明显上升？历史翻页为何越来越慢？

群聊先从明确的小群规则开始，区分发送者提交次数与向接收设备交付的次数。观察工作量、队列、分配和尾部时延，再讨论批量、索引、隔离或更换推送策略。

01.10–01.11、02.09–02.12 作为后续语言与算法深化，使用需要它们的具体问题展开。

**验收：** 提交可复现输入、假设、观测和优化对照，并说明正确性与退化条件。上游 README 的性能描述不替代自己的实验。

## S5：消息可靠性、离线恢复与多端同步

**入口：** 理解并发、事务、日志、取消与基本性能模型。

**学习顺序：** [08 卷](./08_distributed/README.md)08.01–08.04 的部分失败、时间、复制与一致性 → [07 卷](./07_cache_messaging/README.md)07.01–07.05 的状态角色与缓存 → 07.06–07.10 的消息、确认、重复、顺序、积压与跨存储边界。

在此基础上学习 08.05–08.09 的分片、协调、共识和可靠任务；09.09–09.10 衔接异步接口与协议演进；06.11–06.12、07.11–07.12、08.10–08.12 完成迁移、派生状态、验证与完整案例。

**P3 按四条链路展开：**

- 发送链路：客户端消息身份、响应丢失、重试和重复显示的处理。
- 历史链路：会话序号、缺口、分页、断线补拉与停止条件。
- 多端链路：设备会话、接收进度、已读进度、会话列表和状态同步。
- 服务端链路：队列、消息转发、存储、在线推送、离线通知与失败恢复。

源码对照 OpenIM 的 msg/send、msgtransfer、push、msg/sync_msg 与 conversation/sync；到客户端部分再固定兼容 SDK 版本。分别核对“服务端受理、持久条件满足、设备处理、用户已读”的证据，不把不同阶段的确认合并成一个成功。

未读数应先定义包含哪些可见消息、删除与撤回怎样处理；只有在明确满足条件的简化模型里，才使用两个序号相减。在线通知也不自动承担完整消息历史的职责。

**验收：** 推演响应丢失、重复请求、断线重连、双端同时登录、消费后崩溃和旧状态迟到。每个案例给出事实保存位置、重试依据、用户可观察结果和修复入口。

## S6：运行、扩容与升级一个长连接系统

**入口：** 能解释 P2/P3 的业务状态和故障边界，已有基本日志、指标和服务目标。

**学习顺序：** 03.11–03.12 的隔离与资源故障 → [12 卷](./12_platform/README.md)12.01–12.03 的制品、容器与本地依赖 → 11.08–11.12 的目标、过载、响应、复盘与成本 → 12.04–12.12 的集群、资源、权限、退出与发布。

10.10–10.11 将版本、迁移、回滚和运行文档加入交付。先解释单实例的启动、连接停止接入、在途处理与退出，再进入集群和发布。

**P4 场景：** 网关滚动升级使客户端重连；一个节点退出后在线状态需要收敛；网络恢复造成重连风暴；离线积压需要追平。分别观察在线连接、发送受理时延、实际交付时延、存储积压与补拉成功率。

容量模型同时考虑连接数、活跃比例、消息速率、群规模、每用户设备数、消息大小和历史保留时间。不能只按在线人数推算系统压力。

**验收：** 交付启动、就绪、发布、摘流、恢复和回滚说明。实际环境与运行记录单独保存，静态配置检查不等于运行保证。

## S7：IM 架构取舍与长期维护

**入口：** 至少完成一个从需求、实现、运行到故障复盘的项目。

[13 卷](./13_architecture/README.md)13.01–13.12 全部展开，结合 10.11–10.12 的写作、协作与维护性评估。需求、状态与模块边界已在前面实践，这里处理多方案、跨团队、迁移和长期成本。

**P5 答辩：** 为一种明确 IM 场景提交完整设计：普通单聊与小群、大群广播、客服会话或团队协作。改变群规模、离线时长、设备数、旧客户端兼容或恢复目标，要求给出可检验的方案调整。

比较单体与服务拆分、写扩散与读扩散、在线通道与历史同步、关系与文档存储、不同保留策略。每个取舍都说明适用条件、失败边界与维护代价，不能把开源项目当前做法当作所有场景的唯一答案。

现有 [D05](../17_architecture.md)、[D06](../18_capstone.md)保留为方案与验收方法的补充，后续按 IM 主线适配。纯 Go IM 路线不要求先学习 AI。

**验收：** 能根据约束选择方案，保留证据不足之处，组织小步迁移，并让他人接手。

## AI 扩展：在 IM 中加入有证据的助手

S3 后可进入 [14 卷](./14_ai/README.md)14.01–14.03 的 Python、数学与模型基础。顺序为：14.01–14.03 → 14.09 数据集与基线 → 14.04–14.07 模型、提示、检索与 RAG → 14.09 评测深化 → 14.08 工具 → 14.10、14.12 运行交付。14.11 微调与多模态按需求选学。

## 怎样安排每次学习与复习

每次只选择一个能够说清的小目标：读需求和定义，画执行过程，预测一个正常输入和一个反例，做一个独立变式，最后记录哪些结论仍未验证。长章按小节拆开，遇到新的数学、工具或系统概念时先安排基础课。

进入新阶段前，用上阶段的一个不同输入复查理解；完成阶段项目后，隔一段时间尝试不看答案重写关键规则。若预测经常与结果不符，先找出缺的是语法、模型还是环境，再回到对应前置。

有经验的学习者可以用同一组验收证明已掌握后跳过相应讲解。只读路线、背术语或跑通参考程序，不能直接跳过独立变式与失败解释。记录模板见[学习进度](../progress.md)。
