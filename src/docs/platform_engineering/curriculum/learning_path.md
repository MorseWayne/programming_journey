## 主线与当前入口

本系列围绕一个虚构的教学 IM 展开，主参照为 **OpenIM**。项目选择、固定版本、已核对源码与教学边界见[IM 主项目](./im_reference.md)。组织、用户、群组和消息均为虚构数据。

14 卷提供完整的语言与计算机知识体系；实际按 S0–S7 跨卷递进。每个阶段依次经历“IM 需求 → 基础理论 → 小模型与练习 → 源码对照 → 失败变式与取舍”。只在相关前置已经讲清时深入上游代码。

当前已完成 150 章：01.01–01.09、01.12、02.01–02.08、03.01–03.12、04.01–04.07、05.01–05.12、06.01–06.12、07.01–07.12、08.01–08.12、09.01–09.12、10.01–10.12、11.01–11.12、12.01–12.12、13.01–13.12、14.01–14.04、14.09。前两章原案例作为基础补充，其余按 IM 主线展开；正文与设计的区别见[编写与能力验收](./assessment.md)。14 卷全部 168 个单元已有具体 IM 练习与验收目标，长篇继续按先修关系完成。

| 阶段 | 从 IM 需求出发 | 阶段成果 |
|---|---|---|
| S0 程序与规则 | 一条消息包含什么，怎样判断输入是否合法？ | 可解释的消息校验程序与边界表 |
| S1 数据与本地工具 | 如何组织多条消息、会话和本地历史？ | P1 本地会话与消息记录工具 |
| S2 进程与网络 | 两个客户端怎样建立连接并交换消息？ | P2 的 HTTP 查询与内存单聊版本 |
| S3 数据与可信业务 | 谁能发给谁，消息如何保存和查询？ | P2 的身份、会话权限与持久历史版本 |
| S4 原理与性能 | 慢接收方、大群和高并发怎样消耗资源？ | 群聊扇出、队列与内存诊断证据 |
| S5 可靠性与同步 | 重复、断线、多设备和节点失败怎样恢复？ | P3 可靠消息、离线补拉与多端同步 |
| S6 运行与交付 | 长连接网关怎样扩容、发布和恢复？ | P4 可运行 IM 与故障演练说明 |
| S7 架构与长期维护 | 规模、历史保留、旧客户端和成本怎样影响方案？ | P5 IM 架构答辩、迁移与接手文档 |
| AI 扩展 | 如何在聊天中提供有权限、有证据的助手？ | 独立评测的资料助手与受控工具 |

## S0：认识一条消息，写清一条规则

**入口：** 从文件、目录、终端、保存、编译与运行开始，不预设 Go 经验。

**学习顺序：** [01 卷](./01_go/README.md)01.01 → 01.02 → 01.03 起步；穿插 [10 卷](./10_engineering/README.md)10.01 的需求边界、10.03 的差异与本地版本记录。

把最初需求限定为“输出一条文本消息，再判断本题允许的输入”：文本是什么类型？长度按字节还是文字计算？用户 ID 能否当作可计算整数？输入为空和明确提供零有何差别？本阶段只保存、计算和判断这些值。

条件、循环和普通函数先学；能够追踪调用后再学递归，理解作用域后再学函数值与闭包。先写出合法、空值、超限和非法格式的预测结果，再逐条核对。

**验收：** 独立修改一条校验规则，解释每个变量和返回结果。此时不预设消息已发送到网络，也不引入顺序保证、幂等和离线恢复。

## S1：从消息列表到本地会话工具

**入口：** 能读写普通函数、循环和失败分支。

先定义消息与会话：会话表示一组交流对象及其历史归属，消息包含本题需要的发送者、内容和标识。用切片保存列表，用 map 按会话查找；用复制与共享示例解释修改会影响谁。接口先用两种内存存储练习，学完文件后再加文件实现。

**验收：** 能改变文件格式或校验规则，解释非法输入和部分读写的处理；能说明正常保存与崩溃耐久性的区别。01.10 泛型、01.11 反射在 S4 后深化；网络标准库在 S2 补学。

**P3 按四条链路展开：**

- 发送链路：客户端消息身份、响应丢失、重试和重复显示的处理。

- 多端链路：设备会话、接收进度、已读进度、会话列表和状态同步。
- 服务端链路：队列、消息转发、存储、在线推送、离线通知与失败恢复。

源码对照 OpenIM 的 msg/send、msgtransfer、push、msg/sync_msg 与 conversation/sync；到客户端部分再固定兼容 SDK 版本。分别核对“服务端受理、持久条件满足、设备处理、用户已读”的证据，不把不同阶段的确认合并成一个成功。

未读数应先定义包含哪些可见消息、删除与撤回怎样处理；只有在明确满足条件的简化模型里，才使用两个序号相减。在线通知也不自动承担完整消息历史的职责。

**验收：** 推演响应丢失、重复请求、断线重连、双端同时登录、消费后崩溃和旧状态迟到。每个案例给出事实保存位置、重试依据、用户可观察结果和修复入口。

## S6：运行、扩容与升级一个长连接系统

**入口：** 能解释 P2/P3 的业务状态和故障边界，已有基本日志、指标和服务目标。

**学习顺序：** 03.11–03.12 的隔离与资源故障 → [12 卷](./12_platform/README.md)12.01–12.03 的制品、容器与本地依赖 → 11.08–11.12 的目标、过载、响应、复盘与成本 → 12.04–12.12 的集群、资源、权限、退出与发布。

10.10–10.12 已把版本、回滚、运行文档、复盘与长期维护成本接入交付。先解释单实例的启动、连接停止接入、在途处理与退出，再进入集群和发布。

**P4 场景：** 网关滚动升级使客户端重连；一个节点退出后在线状态需要收敛；网络恢复造成重连风暴；离线积压需要追平。分别观察在线连接、发送受理时延、实际交付时延、存储积压与补拉成功率。

容量模型同时考虑连接数、活跃比例、消息速率、群规模、每用户设备数、消息大小和历史保留时间。不能只按在线人数推算系统压力。

**验收：** 交付启动、就绪、发布、摘流、恢复和回滚说明。实际环境与运行记录单独保存，静态配置检查不等于运行保证。

## S7：IM 架构取舍与长期维护

**入口：** 至少完成一个从需求、实现、运行到故障复盘的项目。

[13 卷](./13_architecture/README.md)13.01–13.12 全部展开，结合 10.11–10.12 的写作、协作与维护性评估。需求、状态与模块边界已在前面实践，这里处理多方案、跨团队、迁移和长期成本。

**P5 答辩：** 为一种明确 IM 场景提交完整设计：普通单聊与小群、大群广播、客服会话或团队协作。改变群规模、离线时长、设备数、旧客户端兼容或恢复目标，要求给出可检验的方案调整。

比较单体与服务拆分、写扩散与读扩散、在线通道与历史同步、关系与文档存储、不同保留策略。每个取舍都说明适用条件、失败边界与维护代价，不能把开源项目当前做法当作所有场景的唯一答案。

现有 [D05](../17_architecture.md)、[D06](../18_capstone.md)保留为方案与验收方法的补充，后续按 IM 主线适配。纯 Go IM 路线不要求先学习 AI。

**验收：** 能根据约束选择方案，保留证据不足之处，组织小步迁移，并让他人接手。

## 怎样安排每次学习与复习

每次只选择一个能够说清的小目标：读需求和定义，画执行过程，预测一个正常输入和一个反例，做一个独立变式，最后记录哪些结论仍未验证。长章按小节拆开，遇到新的数学、工具或系统概念时先安排基础课。

进入新阶段前，用上阶段的一个不同输入复查理解；完成阶段项目后，隔一段时间尝试不看答案重写关键规则。若预测经常与结果不符，先找出缺的是语法、模型还是环境，再回到对应前置。

有经验的学习者可以用同一组验收证明已掌握后跳过相应讲解。只读路线、背术语或跑通参考程序，不能直接跳过独立变式与失败解释。记录模板见[学习进度](../progress.md)。
