## 镜像能启动，为什么业务仍可能不可用

任务服务打包成镜像并启动，但数据库还未就绪，新的实例没有恢复状态，旧客户端又继续访问退出中的节点。运行平台与应用之间需要清楚的责任划分。

先修：[B04 容器](../../backend_basics/04_local_tools.md)、[系统讲义](../03_systems/core.md)、[网络讲义](../04_networks/core.md)、[可靠性讲义](../11_reliability/core.md)。

## 一、制品、配置与运行状态

制品描述要运行哪份程序及依赖，配置描述环境和规则，运行状态描述当前实际发生了什么。同一个镜像在不同配置下可能表现不同，不能只记录源代码提交就声称环境完全可重现。

镜像标签方便引用，但可以被更新；摘要帮助识别具体内容。发布记录还需关联配置版本、数据模式和需要的依赖条件。

把所有环境差异打进代码，会增加制品数量；把所有行为放进无校验配置，又会使变化难以理解。应定义稳定配置入口与验证规则。

## 二、三种 namespace 的含义不同

| 名称 | 主要组织什么 |
|---|---|
| Linux namespace | 进程看到的部分系统资源视图 |
| Kubernetes namespace | 集群 API 资源的命名与管理范围 |
| 业务 tenant/team | 应用数据、身份与业务隔离范围 |

一个范围正确，不意味着另外两个自动正确。将业务 team-a 作为字符串传给数据库，还需要可信身份；把 Pod 放到某个集群命名空间，也不自动满足所有网络隔离要求。

## 三、控制循环怎样实现期望状态

平台记录期望，例如某个工作负载需要三个副本。控制器观察当前状态，采取动作缩小差异，再继续观察。

这是持续协调过程，不是提交声明后瞬间完成。调度资源不足、镜像不可用、依赖失败和健康检查都可能阻止收敛。

```text
期望状态 → 观察差异 → 发起动作 → 等待与观察 → 再次协调
```

理解这一点后，就不会把“配置已经提交”和“业务已经稳定运行”当成同一事件。排障需要查控制器、对象状态与应用日志各自的证据。

## 四、副本数与数据状态

无状态处理可以把业务事实放在共享存储中，增加实例扩展处理能力；若每个实例只保存自己的内存余额，增加副本就会产生多份互不一致的状态。

StatefulSet 等对象帮助组织实例身份和相关资源，但不替业务实现复制、共识和恢复。稳定名称与业务状态一致性是不同机制。

增加应用副本还会放大下游需求。例如每副本最多 20 个数据库连接，十个副本可能带来约 200 个连接上限；数据库是否承受得住，需要共同预算。

## 五、资源声明影响等待与失败

request 参与调度与资源分配考虑，limit 对运行用量形成约束。CPU 达到配额可能增加等待，内存触及限制可能触发终止。

因此应观察应用、容器和主机三个视角。宿主机空闲而应用受限并不矛盾，调整资源前先理解配额与实际负载。

数据 volume 的生命周期也应独立解释。容器重建后还能看到数据，是因为存储被保留，不是进程内存继续存在。

## 六、启动与退出要遵循应用依赖

启动过程可能需要加载配置、建立存储连接、恢复状态、校验版本，之后才可接流量。

startup、readiness、liveness 关注不同条件。暂时访问不到数据库时，重启所有实例可能加重故障；探针应针对重启是否真能帮助恢复来设计。

退出时需要限制新业务、影响未来选路、处理在途任务、保存恢复信息并关闭依赖。信号传达、路由传播与请求完成并不同步。

如果客户端使用独立服务发现直接选节点，平台 Service 的就绪变化不自动控制这条路径。必须验证真实调用方式。

## 七、发布策略不能脱离数据兼容

滚动、蓝绿和金丝雀提供不同流量与版本切换方式。无论采用哪一种，新旧代码和数据都可能短时并存。

例如新版本写入旧版本无法解释的状态，切回旧镜像并不能完成安全回滚。需要提前设计兼容读取、扩展与收缩、回填和清理窗口。

灰度应有明确范围、观察时间与停止条件。随机少量流量适合某些服务，按团队或对象固定路由又适合另一些状态问题，需要根据业务判断。

## 八、平台应减少重复决策负担

一套平台提供可用的默认配置、可观察性、权限边界与运行说明，让接入者少重复处理相同问题。它也需要清楚说明不能保证什么。

过度模板化会把特殊业务埋进复杂参数；完全自由配置又可能让每个团队重复踩坑。应通过真实接入、升级和故障案例评估抽象。

### 分层练习

1. 为一次发布关联程序、镜像、配置和数据模式版本。
2. 解释副本启动失败时，平台状态与应用状态各提供什么证据。
3. 为内存服务扩成两副本构造数据分裂反例。
4. 写出启动、就绪、摘流和退出的依赖顺序。
5. 给新字段迁移设计灰度与回滚后数据解释。
