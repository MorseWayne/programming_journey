## 本课问题与前置

演示时三个问题都答对，能否上线给整个团队用？前置：第 10、14–15 课。建议用时 4 小时。

目标：定义评测单位和分母，拆开检索与生成，记录回归，判断哪些结论证据不足。

## 把“好用”拆成可观察条件

| 层面 | 问题 | 一个可用指标 |
|---|---|---|
| 检索 | 需要的资料是否出现在候选中 | hit@k |
| 回答 | 每条断言是否由材料支持 | 人工核对支持比例 |
| 任务 | 工具效果是否符合请求 | 任务成功率 |
| 权限 | 是否返回无权查看的数据 | 越权案例数 |
| 运行 | 用户要等多久、付多少成本 | 端到端延迟、调用量与实际计费 |

本课的 hit@2 表示“前两条至少命中一条标注相关来源”的查询比例，不是检索出所有相关文档的比例。拒答正确率的分母只包含应拒答样本。把不同任务混成一个准确率，会掩盖关键问题。

## 实验：先跑固定样本，再主动找失败

```bash
cd labs/platform_path
python3 ai/agent_lab.py evaluate
```

预期输出 8 个案例、4 个可回答、4 个应拒答，固定样本上的 hit_at_2 和 correct_refusal_rate 均为 1，model_calls 为 0。

这是管线自检，不是模型能力成绩。数据量小、词汇与文档接近、没有实际生成；不能用这个 100% 对外宣称问答准确率。

将 cases.jsonl 复制为个人评测文件，加入以下案例：同义改写、错别字、中文问题、半相关问题、过期材料、互相矛盾的材料、跨租户请求、包含工具指令的材料。

```bash
python3 ai/agent_lab.py evaluate --cases /你的实验目录/my_cases.jsonl
```

路径需要替换为自己创建的文件。每行沿用 id、tenant、query、expected_sources、should_refuse 五个字段。先标注预期，再调整实现，保留部分案例作未参与调试的验证集。

## 一个完整的改进实验

1. 固定文档版本与查询集，保存基线。
2. 只改变一个因素，例如分词、检索方式或提示版本。
3. 同时检查正常问题和拒答问题。
4. 对每个回归保留输入、证据与解释。
5. 有真实模型时记录模型标识、参数、原始输出、耗时和实际 token 用量。

随机输出需要重复测量并报告波动；外部模型裁判也有偏差，关键权限和副作用仍需确定性检查与人工抽查。

<details>
<summary>练习反馈：新模型更会回答，为什么仍可能不适合上线？</summary>

可能更容易编造、拒答变差、费用超预算，或完成同样任务用了更多工具调用。上线条件要覆盖成功、风险和运行成本，不能只优化单个得分。

</details>

## 上线门槛与回滚

写出本场景的失败成本，再定义门槛。低风险内部检索可以先面向小范围用户；会创建或修改业务数据的工具需要独立批准和审计。阈值由业务需求决定，不把课程示例中的分数当通用标准。

达标证据：至少 12 个独立补充案例、一份回归说明、上线与回滚条件。下一课：[架构决策与迁移](./17_architecture.md)。
