## 小需求：让程序连接自己的数据库

后面会使用 Go 程序之外的数据库服务。先理解这些服务如何运行、在哪里监听、配置从哪读取，才能区分环境问题和程序逻辑问题。

本页是学习时的操作说明。第一轮可先读懂命令和结构，再按个人条件准备环境；教材内容修订本身不要求启动这些服务。

## 环境变量与程序配置

环境变量是进程启动时可读取的命名配置，例如监听地址。与源码中的局部变量不同，它通常由启动环境提供，程序通过标准库读取。

```go
// 片段：在 main 内使用，需引入 os 与 fmt。
address := os.Getenv("APP_ADDRESS")
if address == "" {
    address = "127.0.0.1:8080"
}
fmt.Println(address)
```

类 Unix shell 可以写 `APP_ADDRESS=127.0.0.1:8081 go run ./b03server` 为这次启动设置值；前提是程序确实读取该变量。B03 的固定地址版本还不会因此改变地址，应先按上面的片段修改配置入口。

PowerShell 的环境变量赋值语法不同，不能照搬这段 shell 写法。课程命令默认使用类 Unix shell，跨系统时先确认相同含义。

配置来自环境变量、文件或命令参数时，都应校验内容。例如端口应合法，超时应有单位；“读取成功”不代表配置正确。

## 镜像与容器的最小模型

**镜像**保存程序及其运行需要的文件，是启动环境的材料。**容器**是从镜像启动的受隔离进程环境。一个镜像可以启动多个容器，各自拥有运行状态。

容器不是业务数据库的备份，也不会自动共享应用内存。进程结束、容器重建和数据文件保留是三件需要分开判断的事。

Docker 是一种管理这类镜像与容器的工具；Compose 用配置文件描述多个服务怎样一起运行。本课使用已经准备好的 MySQL 与 Redis 镜像，不要求先编写自己的镜像。

## 端口映射为什么有两边

```text
127.0.0.1:34067:3306
```

可以把这个配置理解为：宿主机本地的 34067 端口转到容器内的 3306。宿主机上的客户端连接前者，容器内部的数据库监听后者。

在容器里访问 127.0.0.1，通常指向该容器自己的网络环境；不应自动当成宿主机。多个容器通信时还需要相应网络与服务名称，这些由 Compose 配置组织。

绑定本机回环地址的练习服务，适合只在自己的电脑访问。这里的范围来自明确绑定方式，不能从“用了容器”就推断服务不会对外暴露。

## volume 与数据生命周期

容器的可写文件层会随具体容器生命周期变化。volume 用于把需要保留的数据放到单独管理的位置；课程的 MySQL 使用命名 volume 保存练习数据。

`docker compose stop` 停止进程，通常保留容器与 volume。删除容器和删除 volume 是不同操作，带删除数据含义的选项需要理解后再使用。

重新启动后看到上次的表，说明使用了保留的数据目录，不是内存自动跨进程存活。B05 会学习怎样查询其中的数据。

## 读懂 Compose 的少量 YAML

YAML 使用缩进组织层次，常见形式为 `键: 值`，以 `-` 开头的项表示列表。缩进必须一致，不能把不同层级随意混合。

```yaml
services:
  mysql:
    image: mysql:8.4
    ports:
      - "127.0.0.1:34067:3306"
```

这只是解释片段，不是完整数据库配置。完整课程文件在 `labs/platform_path/compose.yaml`，还定义了环境、数据卷和健康检查。

镜像标签 mysql:8.4 表示版本系列。某系列标签可能更新补丁；需要复现实验时，记录实际镜像版本或 digest，而不是假设标签永久指向相同内容。

## 学习时使用的命令

先根据自己的系统安装 Docker 与 Compose，并确认工具可用。进入本仓库的 `labs/platform_path` 目录后：

```bash
docker compose version
docker compose config --quiet
docker compose up -d --wait --wait-timeout 90
docker compose ps
```

version 查看工具版本；config 检查配置；up 创建或启动服务；-d 表示在后台运行；--wait 等待服务达到相应运行或健康条件。健康检查条件也需要看配置，并不证明所有业务已经正确。

进一步观察：

```bash
docker compose logs mysql
docker compose exec mysql mysql -uroot -pjourney-local-only journey_lab
```

logs 查看服务日志；exec 在服务容器中执行命令。第二条里的第一个 mysql 是 Compose 服务名，第二个 mysql 是数据库客户端程序。`-uroot` 选择用户，`-p...` 提供课程公开本地密码，journey_lab 是练习数据库名称。

此时进入的是 SQL 客户端，B05 会讲在里面写什么。退出数据库客户端使用 `exit`，回到终端后可用 `docker compose stop` 停止练习服务并保留数据。

## 端口、权限与依赖故障怎样排查

端口占用先确认是否已有进程监听；数据库未就绪先看容器状态与日志；提示 Docker 权限不足时，应按本机管理方式配置访问，不要把它当作 SQL 语法错误。

磁盘、内存和网络下载也会影响环境。没有 Docker 时，可以继续阅读 SQL 和原理，动手记录保持未执行，不必用猜测填写结果。
