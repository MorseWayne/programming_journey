## 小需求：另一个程序也想查看任务

把任务保存在当前变量里，只能由当前程序直接访问。希望浏览器或另一个程序查询时，需要约定如何找到提供数据的一方、怎样发送请求、怎样读懂返回结果。

**客户端**主动发起请求，**服务端**监听并处理请求。一个程序可以在某条链路上当服务端，在调用数据库时又作为客户端。这是交互角色，不是某种固定硬件名称。相对当前处理步骤，发起请求的一方常称上游，被调用的依赖常称下游。

## 地址、端口与连接

IP 地址帮助网络定位主机或接口；端口帮助在该主机上找到某个监听入口。`127.0.0.1:8080` 表示通过本机回环地址访问端口 8080。

回环地址指向当前所在的主机或网络环境，不是固定指向某台远程电脑。容器拥有自己的网络环境时，其 localhost 也不一定是宿主机，B04 再展开。

**监听**是服务端准备接受连接；**连接**是双方通信的一条逻辑通道。多个客户端连接可以访问同一个监听端口，不是每个用户都要配置一个新的服务端端口。

### 域名与 DNS

域名是易读名称，DNS 帮助把名称解析为网络地址。域名正确、解析成功、端口可达、应用返回正确结果，是不同步骤。

遇到故障时按步骤定位：名称是否解析、目标是否能连接、协议是否能交互、业务是否成功。不能把所有错误都称为“网络不好”。

## 协议为何必不可少

**协议**是双方对传输内容和行为的约定。即使字节成功到达，如果一方发送文本、另一方按另一种二进制格式解析，也无法正确协作。

可以先用分层视角理解：网络地址负责到哪里，传输机制负责怎样运送，应用协议负责怎样组织请求与响应，业务契约负责操作究竟意味着什么。

| 层面 | 一个概念例子 | 还没有解决的事 |
|---|---|---|
| 寻址 | IP 与端口 | 数据代表什么 |
| 传输 | TCP | 一次业务操作是否成功 |
| 应用消息 | HTTP | 用户是否有权领取奖励 |
| 业务规则 | 任务领取接口 | 具体实现是否满足约定 |

这里是学习上的职责拆分，不要求第一轮记住全部网络模型的每一层名称。

## TCP：有序字节流

TCP 为应用提供有序字节流。字节可以分多次传输和读取，一次发送并不对应一次接收。

```text
应用想发送：hello 和 world
接收方可能读到：he / llow / orld
```

接收方需要协议判断哪几个字节组成一条完整消息。可以用长度、分隔符或现成应用协议定义边界；C04 会用长度头和 io.ReadFull 做具体推导。

TCP 处理传输中的一些丢包与重排，并不意味着远程业务已完成。例如发奖成功后返回连接断开，客户端仍可能不知道结果，C08 再讨论。

UDP 是另一类传输方式，保留数据报边界，但不提供与 TCP 相同的可靠有序流保证。是否使用它取决于应用需求，入门 HTTP 练习先不扩展到这一方向。

## HTTP：请求与响应

HTTP 为客户端与服务端规定方法、目标、头部、状态和正文等内容。下面是用于理解的 HTTP/1.1 文本示意：

```http
GET /tasks HTTP/1.1
Host: 127.0.0.1:8080
Accept: application/json
```

方法 GET 表示读取请求，路径 /tasks 指向应用中某类资源。头部提供描述信息；请求还可以带正文，例如提交 JSON。

```http
HTTP/1.1 200 OK
Content-Type: application/json

[{"id":"t1","title":"学习网络"}]
```

状态码说明协议与应用报告的结果类别，正文携带具体内容。HTTP/2、HTTP/3 的传输组织方式不同，不能将上面的文本逐字当成所有 HTTP 版本的线格式；方法和响应等基本语义仍可作为理解入口。

### 常见状态码先认识这些

200 常用于成功，400 表示请求问题，401 涉及身份认证，403 表示拒绝授权，404 表示未找到目标，500 表示服务端处理异常。它们不代替详细业务约定；收到 200 也要知道接口承诺到了哪一步。

## URL 每一部分是什么意思

```text
http://127.0.0.1:8080/tasks?done=false
```

http 是协议方案，127.0.0.1 是主机，8080 是端口，/tasks 是路径，? 后面是查询参数。查询参数仍是文本，需要应用解析和验证。

HTTPS 在通信上使用 TLS 提供加密、完整性和身份相关保护。它不会自动判断当前用户是否有权查看另一个团队的任务，权限仍属于应用职责。

## 超时是等待预算

连接建立、发送、等待服务端和读取响应都可能耗时。设置超时，是决定调用方愿意等待多久，不代表到点就能让对方撤销已经发生的操作。

后续练习会显式设置客户端超时。先记住“收到明确失败”与“没有及时收到结果”不同，C08 再引入幂等与查询解决这种未知。

## 不依赖运行环境的练习

给 URL 标出地址、端口、路径和参数；按顺序画出读取任务的请求与响应；说明“连接被拒绝”“404”和“JSON 内容错误”分别最先检查哪一层。

同一个 IP 上可以有多个端口，同一个监听端口也可以接受多个连接。进程与端口不能简单一一对应。
