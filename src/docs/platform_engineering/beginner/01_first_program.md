## 这节课从哪里开始

你只需要会用编辑器创建并保存文本文件。本课不要求已经理解变量、函数或服务端。

第一个需求很小：让计算机显示“欢迎来到练习平台”。我们会解释代码在哪里、怎样让它执行，以及屏幕上的结果从哪里来。

## 先认识四个东西

**源代码**是人写下的程序文本。Go 源码文件通常以 `.go` 结尾。**编辑器**负责编辑和保存文本，**终端**用于输入命令，**Go 工具链**负责检查、编译和运行程序。

编译把源码转换为机器能够执行的程序。程序开始运行后，会按照规定处理数据和执行指令。后面的 B01 再解释进程和内存；今天先分清“文件里写了什么”和“实际运行了什么”。

### 文件、目录与当前目录

目录用于组织文件。终端每时每刻都在某个当前目录，许多命令会以它为起点寻找文件。

| 写法 | 含义 |
|---|---|
| `go-course/a01/main.go` | go-course 目录里，a01 子目录中的 main.go |
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `mkdir a01` | 创建名为 a01 的目录 |
| `cd a01` | 把当前目录切换到 a01 |
| `cd ..` | 返回上一级 |

代码块标记为 bash 的内容是终端命令，标记为 go 的内容保存到源码文件。不要把 `package main` 当终端命令，也不要把 `go run .` 写进 Go 文件。

## 准备 Go

按照 [Go 官方安装页](https://go.dev/doc/install)选择自己操作系统对应的安装包，完成安装后重新打开终端，输入：

```bash
go version
```

预期看到一行版本与系统信息，例如包含 `go1.x` 和系统/架构名称。本课程配套示例声明 Go 1.24+，A 篇使用的基础语法不依赖新特性。

若提示找不到 go，先检查安装是否完成、终端是否重新打开，以及安装说明中的命令搜索路径。不要把这种工具问题误判为源码错误。

## 创建独立的练习位置

选择自己的学习目录，在终端执行：

```bash
mkdir go-course
cd go-course
go mod init example.com/go-course
mkdir a01
cd a01
```

若目录已存在，可以直接进入，不必重新创建。`go mod init` 在 go-course 下创建 `go.mod`，记录这一组代码所属的模块。这里的 `example.com/go-course` 是练习用模块名，不需要购买域名或发布网站。A08 会详细解释模块与包。

现在用编辑器在 a01 目录创建 `main.go`，保存以下完整程序：

```go
package main

import "fmt"

func main() {
    fmt.Println("欢迎来到练习平台")
}
```

## 按行读懂它

`package main` 声明当前文件属于 main 包。可以先把包理解为一组放在一起、能够协作的代码。main 包有特殊用途：可以作为可执行程序的入口所在包。

`import "fmt"` 引入标准库中的 fmt 包。标准库随 Go 提供，fmt 包里有输出和格式化文本的工具。

`func main()` 定义名字为 main 的函数。函数是一段可以被调用的工作步骤；这里的 main 是程序启动后进入的入口。圆括号目前为空，表示我们没有为它声明输入参数。

花括号 `{` 和 `}` 围住函数要做的事。`fmt.Println(...)` 调用 fmt 包里的 Println，把括号里的内容输出并换行。双引号里的内容是字符串，也就是文本。

点号在这里连接“包名”和“包内工具名”。名字的拼写和大小写需要准确，Println 与 println 不是相同写法。

## 第一次运行与预测

在 a01 目录执行：

```bash
go run .
```

点号表示当前目录的包。Go 会检查并临时编译它，再运行。预期输出：

```text
欢迎来到练习平台
```

现在把打印内容改成“今天完成第一课”，保存，再运行。未保存时，终端读取的仍可能是上次保存的文件内容。

`go build .` 用来生成可执行文件而不直接运行，这是另一种工具用途，当前练习先用 go run 即可。`gofmt -w main.go` 会整理缩进与格式，不会替你修正业务逻辑。

## 三类错误怎样区分

| 现象 | 大致发生在哪一步 | 本课中的例子 |
|---|---|---|
| 终端找不到命令或文件 | 工具与路径 | 不在 a01 目录，或 Go 未安装 |
| 编译报错 | 代码不符合语言规则 | 少一个右括号，或使用未引入的包 |
| 输出与预期不同 | 程序能执行但逻辑不对 | 打印了错误的文字 |

错误信息常含文件名和行号。先找到对应行，看第一条有意义的错误，再检查括号、拼写和引入。一次修改一个问题更容易理解。

## 自己完成三个小变化

1. 连续输出任务名称和奖励说明两行文本，预测输出顺序。
2. 故意删掉一个右括号，观察错误位置，再恢复它。
3. 回到 go-course 根目录，在终端执行 `go run ./a01`，解释路径为什么变化而程序不变。
