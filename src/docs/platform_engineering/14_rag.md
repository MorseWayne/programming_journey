## 需求场景：助手需要解释“超时后能否重新发奖”

工程师需要当前平台规则，而资料里有旧版说明、不同游戏的私有文档和不完整片段。一个看起来流畅的回答，可能遗漏“必须使用原请求 ID”这个关键前提。

本课先区分模型生成与资料检索，再从可解释的基线逐步理解 RAG。目标是能解释文档怎样变成候选证据，为什么相似不等于正确，以及何时应该承认证据不足。

## 基础理论：模型在做什么

语言模型将文本表示为 token 序列，并根据上下文预测后续 token。token 不等于一个汉字或一个单词，具体划分取决于分词方式。训练改变模型参数，推理在给定参数下根据输入产生输出；向提示中加入文档通常不等于重新训练模型。

模型学习到的语言与知识模式，能够帮助组织答案，但流畅输出不自动证明事实准确。它可能沿用过期信息、补全未提供的细节，或忽略问题条件。

上下文窗口限制本次可处理的输入输出规模。把所有资料堆进去既有成本，也会增加无关信息和冲突。因此需要选择材料、保留来源并检查回答。

## RAG 将哪几个问题分开

RAG 在生成之前检索相关资料，并将资料提供给模型作为上下文。可以拆成两条路径：

```text
准备资料：原文 → 清洗与分块 → 元数据和权限 → 建索引
回答问题：可信身份 → 查询 → 权限过滤 → 检索与排序 → 证据 → 生成与核对
```

检索与生成结合的原始研究可阅读 [Lewis 等人的 RAG 论文](https://arxiv.org/abs/2005.11401)；本课采用便于解释的词项基线，与论文模型实现不同。

资料准备决定哪些内容可被找到，检索决定本次看到什么，生成决定怎样表达。任一层出错都可能影响答案，但修复方式不同。

例如根本没有最新版文档时，更换生成提示不能凭空获得可信新规则；找到正确材料却漏掉限制条件时，需要检查分块和答案支持程度。

## 检索基础：关键词、向量与排序

### 从关键词交集开始

课程将英文文本切成词集合，用查询与文档共有词数排序。假设查询是 `{timeout, retry}`，文档包含这两个词就得到 2 分，只包含 timeout 得到 1 分。

这个模型简单，便于解释；它不区分常见词与稀有词，也不理解完整语义。更成熟的词项检索会考虑词频、区分能力和文档长度等因素。

### embedding 与相似度

embedding 将文本映射成数值向量，用距离或相似度表达模型学到的关联。余弦相似度比较方向，可以写为点积除以两个向量长度之积。

教学向量 `(1,0)` 与 `(0.8,0.6)` 的长度均为 1，相似度为 0.8；与 `(0,1)` 的相似度为 0。这个计算只解释几何关系，不能把某个维度直接理解为“真实性”或“权限”。

向量检索可能找到词面不同的同义内容，也可能返回主题相关却不回答问题的片段。近似最近邻索引进一步用一定召回损失换取检索效率；是否需要它取决于数据规模与测量。

### 为什么还会重排

初步检索通常先保留一批候选，再用更昂贵的相关性判断重排。混合检索可以结合词项与向量，但分数尺度、延迟和错误类型都需要评测，不能直接断言机制越多越准确。

## 分块与元数据：保留足够的前提

chunk 是可单独检索的片段。按固定长度切分可能把规则和例外拆开；过大的片段又可能混入无关内容。可以从标题、段落和语义完整性入手，再用真实问题验证。

每个片段应能关联文档 ID、版本、位置、所属租户和有效时间。这样才能追溯引用、替换旧版本，并解释为什么同一问题在不同日期得到不同依据。

课程 Document 只有 id、tenant、text、version；有效期、段落位置和更细权限是后续扩展任务。不能把正文提出的完整设计当作现有原型已经实现。

## 机制推导：先权限，后材料进入上下文

如果无权访问的文档已经进入模型上下文，再让模型“不要透露”并不能作为权限边界。执行系统应在检索或取文档阶段落实授权，并在展示和工具操作时继续检查。

课程先按 tenant 过滤再排序。tenant 在命令行演示中由实验者提供；面向真实用户时必须来自第 12 课讨论的可信身份，不能允许用户任意改参数越权。

## 实验一：相关、无权与合法跨租户查询

```bash
cd labs/platform_path
python3 ai/agent_lab.py retrieve --tenant game-a --query "old owner token"
python3 ai/agent_lab.py retrieve --tenant game-a --query "private billing escrow"
python3 ai/agent_lab.py retrieve --tenant game-b --query "private billing escrow"
```

第一条应命中 fencing-v1，第二条拒绝，第三条找到 billing-v1。结果状态 evidence_found 仅表示找到了候选证据，当前程序没有生成自然语言答案。

## 实验二：主动制造“相关但不足”

```bash
python3 ai/agent_lab.py retrieve --tenant game-a --query "timeout dragon"
```

基线可能因为 timeout 命中资料，但资料无法解释 dragon。这个反例说明“至少重合一个词”不能判断材料是否覆盖完整问题。

请分别加入同义改写、中文、错别字、过期说明和矛盾材料。当前英文正则分词会丢失中文词项，这是已知实现边界；修复它应单独评测，不能用给文档硬塞测试词的方法掩盖问题。

### 证据不足需要明确行为

未找到资料、资料缺少前提、资料相互矛盾、版本无法确定，是不同问题。可以拒答、说明限制或请求必要条件。仅提高相似度阈值可能减少误命中，也可能增加漏检，要同时检查两种代价。

## 条件实验：让模型根据材料回答

有个人测试环境后，再加入生成步骤。约定输出回答、引用来源与不确定项；保存查询、候选片段、最终上下文、模型标识、提示版本、原始输出和耗时。

逐条核对答案断言：哪段材料支持它？材料是否包含所需前提？引用是否真的对应这句话？一句话附了引用，并不意味着引用支持其中所有内容。

资料中的“忽略规则”“创建工单”等文本属于待处理数据，不应因此获得执行权限。模型建议调用工具后仍需要独立的执行边界，第 15 课展开。
