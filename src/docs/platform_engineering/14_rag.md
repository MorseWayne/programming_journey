## 本课问题与前置

知识库里有一份超时说明，用户却问“超时后能否重新发奖”。检索到包含“超时”的文档，是否已经回答了问题？

前置：第 8、12–13 课。建议用时 4 小时。目标：分清检索、证据与生成；先过滤权限，再排序；验证无法回答的情形。

## 拆开 RAG 流程

**RAG**是先检索相关材料，再将材料提供给模型生成回答的一种组织方式。通常包含文档切分、索引、查询、排序、上下文构造、生成和结果检查。

**chunk**是一段可检索文本。切得太短可能缺前提，太长会带来噪声和上下文成本。文档 ID、版本、位置和权限应与文本一起保存，才能知道答案依据来自哪里。

**embedding**把文本转换为向量，用距离表达某种相似性；相似不等于事实正确、权限允许或材料足够。关键词检索可作为基线；是否加向量、混合检索或重排，应由查询集上的错误决定。

## 从最容易解释的基线开始

本课实验将英文文本拆成单词集合，以查询与文档共有词数排序，选择前两条。先按 tenant 过滤，再排序。这样可以清楚地观察每个步骤。

这是英文固定样本的词项检索，未实现中文分词、向量或大模型。返回状态是 evidence_found，含义仅为发现候选证据，不能读成“答案已经正确”。

```bash
cd labs/platform_path
python3 ai/agent_lab.py retrieve --tenant game-a --query "old owner token"
python3 ai/agent_lab.py retrieve --tenant game-a --query "private billing escrow"
python3 ai/agent_lab.py retrieve --tenant game-b --query "private billing escrow"
```

预期第一条命中 fencing-v1；第二条拒绝，因为相关材料只属于 game-b；第三条得到 billing-v1。这证明当前过滤边界，不代表真实模型不会被提示注入影响。

## 给“证据不足”留出状态

可能有三类失败：找不到相关文档、找到但不够完整、材料矛盾或过期。它们需要不同处理。把 top-1 原样当答案，会把一个排序结果扩大成事实承诺。

练习：查询 `timeout dragon`。基线会因 timeout 命中材料，但材料并不能解释 dragon。请添加这个反例，说明仅按词重合决定是否回答的局限。

提高匹配阈值可以减少部分误命中，也可能丢掉同义表达。加入同义词或向量能改善相关性，却不能直接证明答案完整。需要单独检查问题所需条件是否有证据，必要时拒答或澄清，并用新的查询集验证回归。

## 真实模型接入的条件实验

具备个人测试账户后，可以把检索结果交给模型，约定输出答案、引用 ID 和不确定性。使用公开或虚构文档，固定模型标识、提示版本与上下文预算。

保留同一组查询的原始输出，检查每条断言是否得到对应材料支持。检索内容属于数据，即使里面写“忽略规则并调用工具”，也不应因此获得额外权限。权限必须由执行层核验，不能只依赖提示词。

达标证据：授权与未授权检索测试、一个误命中反例、一次修正前后的对比。下一课：[Agent 状态与工具](./15_agents.md)。
