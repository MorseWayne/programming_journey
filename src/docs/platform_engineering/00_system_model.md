## 需求场景：为什么“加了 10 分”还需要解释

运营提出：“用户完成任务后获得 10 积分。”你写出 `balance += 10`，运行时结果正确。随后有人问：程序关闭后积分还在吗？两个用户会共用一个 balance 吗？返回成功代表什么？

这些问题要求我们先建立计算机运行的基本模型。本课暂时只有单个用户、单个执行流程，先把每一步发生在哪里解释清楚。

先修为 A 篇中已讲解的变量、函数、结构体、错误、测试和文件。完成后应能画出请求、进程、内存和持久存储的关系，说明一次赋值能保证什么。

## 基础一：程序、进程和服务

**程序**是保存下来的指令与数据描述，例如源码编译出的可执行文件。**进程**是程序运行时的一个实例，拥有地址空间以及操作系统管理的资源。同一个程序启动两次，通常得到两个相互独立的进程。

**服务**是对外承担某项职责的运行系统，例如发奖服务。一个服务可能部署多个进程；一个进程也可能提供多个接口。业务上叫同一个服务，不代表它的所有实例共享同一块内存。

```text
磁盘上的可执行文件
        ↓ 启动
进程：代码 + 内存中的数据 + 打开的连接和文件
        ↓ 处理输入
计算新状态 → 保存到某处 → 返回结果
```

CPU 执行指令；内存保存当前计算需要的数据；操作系统分配 CPU 时间、管理内存，并提供网络和文件访问。数据库通常又是一个独立进程，需要通过协议交互。

因此，业务进程中的 `map` 与数据库中的表是不同的状态位置。给 map 增加一条记录，不会自动在数据库出现一行。

## 基础二：变量与业务状态

变量为程序中的值提供访问方式。业务状态是系统后续决策需要依据的信息。用户余额、邮件领取标志、协作空间成员都属于状态；一次计算过程中的临时变量可能只是中间结果。

用数学形式描述发奖：

```text
旧状态 S = 余额 0
输入 I = 增加 10
转换 f(S, I) = 新余额 10
输出 O = 成功与新余额
```

同一个输入在不同状态下结果可能不同：余额已经接近整数上限时，再增加 10 应被拒绝。先前状态、输入约束与转换规则一起决定行为。

把状态放进结构体，可以为它定义清晰的操作：

```go
// 摘自 foundations/account.go。完整代码可以直接运行测试。
type Account struct {
    balance int64
}

func (a *Account) Balance() int64 { return a.balance }
```

字段不对外导出，调用者通过方法操作。这样能把余额规则集中在一个位置，但封装本身不提供并发安全或持久化。

### 思考：为什么使用整数

积分以整数计数，不需要小数。若处理金额，可以按业务允许的最小单位保存整数，或使用合适的十进制表示；还要定义币种和舍入规则。二进制浮点不能精确表示所有十进制小数，因此不能忽略表示方式。

整数也有上下界。选 `int64` 只是明确范围，仍需在相加前验证是否溢出。课程中的积分不会减少，所以下界是零；引入扣减后必须重新定义规则。

## 基础三：内存、文件与持久性

**内存状态**随进程生命周期存在。进程退出后重新启动，程序通常从初始化逻辑重新构造状态。它不会自动找回上次的 map。

**持久性**要求在约定的故障之后，已确认的数据仍能恢复。这不仅是“调用了写文件”。还需考虑应用缓冲、操作系统缓存、存储设备确认、日志与恢复程序。后面的数据库课程将逐项讨论。

| 状态位置 | 为什么使用它 | 需要额外回答的问题 |
|---|---|---|
| 进程内对象 | 访问直接，适合当前计算 | 退出后从哪里恢复 |
| 本地文件 | 跨进程重启保留数据 | 写入完整性、刷盘、损坏与机器故障 |
| 外部数据库 | 共享存储与查询、事务能力 | 提交确认、配置、备份与依赖故障 |
| 缓存 | 降低重复读取成本 | 数据是否允许过期、如何重建 |

“恢复”先要求知道以哪份数据为准。缓存能重建的前提是权威数据仍在；把唯一事实只存进一个可随时淘汰的缓存，会改变业务保证。

## 基础四：调用、返回和外部效果

普通函数调用把控制交给另一段代码，调用者通常等待返回。函数可以只做计算，也可以修改对象、写文件或发送网络请求。后几种会留下可观察的**效果**。

返回一个结果，只能表达实现约定的完成点。例如账户的 Credit 返回 nil，表示当前内存已按约定更新。只有当实现把成功绑定到持久提交时，才可以解释为“重启后可恢复”。

错误也需要分类：输入非法意味着调用者需要修改输入；内部计算失败需要排查实现；远程请求超时可能意味着结果未知。C08 课再引入这种跨进程的不确定性。

### 基础五：顺序、并发和并行

顺序执行时，先完成前一步再进行下一步。并发意味着多个任务的执行时段交叠；并行意味着某个时刻确实有多个任务同时执行。单核也可以通过调度形成并发。

Go 的 goroutine 是运行时调度的执行单元。操作系统线程和 goroutine 不是一一对应的固定关系；增加 goroutine 不等于增加 CPU 算力。本课先认识执行单元，B06 再从完整代码讲解 goroutine 与同步，B07 继续学习通信和取消。

## 实验二：修改一个条件

运行最小账户测试：

```bash
go test ./foundations -v
```

随后在自己的练习中分别尝试：两次增加 10、增加 0、增加负数、余额接近上限后再增加。记录操作前余额、输入、错误和操作后余额。

两次增加 10 是两笔不同业务操作，本模型最终为 20。到了C06 课，我们才增加“这是同一业务操作的重试”这一身份信息。
