## 按阶段进入，不按文件夹通读

从 [01.01 程序与工具链](./curriculum/01_go/01_program_toolchain.md)开始；[S0–S7 学习路线](./curriculum/learning_path.md)按前置和业务需求跨卷安排顺序，[14 卷总纲](./curriculum/README.md)用于按领域查知识。AI 是按需求学习的扩展方向。

每章可以分几次完成。先读当前业务问题和必要基础，自己预测最小例子的结果，再跟着正文推导机制；最后改变一个条件，观察或解释为什么失败。遇到术语断层，查[概念与先修索引](./concept_map.md)回到第一次完整讲解的位置。

## 每次学习的四步

1. **说清需求和边界。** 谁发送、谁接收、目标会话是什么；哪些结果是现行合同，哪些只是教学提议。
2. **推导最小模型。** 不运行时先画变量、状态、时间线或数据结构，写出输入、步骤和预期输出。
3. **完成实践与反例。** 按章内环境运行可执行示例；再独立改变一个条件，记录正常、边界和失败结果。未运行的纸上题明确标为推导。
4. **回到业务结果。** 解释当前示例最多保证到哪里；例如传输层确认、S2 进程内受理、持久化与设备收到属于不同层。

学习与实践交替进行。测试、Git、授权、容量和观测在第一次需要时进入，后续阶段再加深；初学 Go 时不要求预先掌握整个分布式或平台卷。

## 先做小项目，再对照源码

P1 本地会话工具 → P2 网络通信与可信历史 → P3 可靠消息和多端同步 → P4 运行与故障恢复 → P5 IM 架构答辩。阶段成果和验收见[学习路线](./curriculum/learning_path.md)，实践目录与环境见[环境页](./environment.md)。

[OpenIM 固定版本](./curriculum/im_reference.md)用于在具备前置后核对具体源码入口。公开项目的实现、课程虚构 IM 的规则和你自己运行的结果需分别标注；不能从一个示例、README 性能数字或一次本地通过推断生产保证。

## 怎样记录掌握程度

把“已阅读、能推导、已运行、独立变式通过、能迁移”分别记在[个人进度模板](./progress.md)。每项实践留下版本、环境、输入、命令或纸上步骤、预期、观察和差异解释。真实效果与性能需要对应负载和测量；没测过就保留未知。

可用下面的提问格式继续学习：

```text
当前阶段、章号和 IM 需求：
我已经理解的前置：
第一次看不懂的概念：
我对示例/失败变式的预测：
实际结果与证据（未运行则注明）：
请从缺失前置开始，用最小例子解释，再让我预测一个变化。
```
