## 先确定起点

课程按已有 Go 开发经历设计，但不会把负责过服务等同于掌握全部底层机制。第一轮从最小状态模型开始，再逐步加入共享、并发、持久化和网络故障。

先阅读[业务场景地图](./business_map.md)，选一个熟悉的动作作为个人对照案例。职责范围可以覆盖整个平台，学习时仍应聚焦一个能解释、能验证的问题。

语法前置是函数、结构体、切片、map、方法与 error。若这些仍影响阅读，先补本站 [Go 基础](../language/go/basic/README.md)；不要求先把全部语言或系统手册读完。

## 三个层次怎样学

| 层次 | 需要做什么 | 进入下一层的证据 |
|---|---|---|
| 基础理解 | 用自己的话定义概念，解释最小例子 | 能预测正常与边界输入 |
| 机制理解 | 改变并发、故障或数据条件，推导原方案为何失效 | 能复现反例并解释修复条件 |
| 业务应用 | 指定成功、失败代价与约束，选择合适机制 | 能迁移到另一场景并写出验收 |

工程深化用于第二轮扩展。第一次遇到共识、复杂索引或框架内部实现时，可以先掌握它在当前问题里的职责，再沿资料继续深入。

每课的业务问题不是装饰。读完后应能回答：需求中的哪句话导致了这个设计？放宽或收紧哪条约束会改变方案？

## 按先修关系做诊断

先写答案，再看解释。每题记为“尚不清楚”“能解释”“已用不同例子验证”，不必用一个总分掩盖局部缺口。

| 诊断问题 | 对应基础 | 回读位置 |
|---|---|---|
| 程序重新启动后，内存余额为何没有自动保留？ | 进程、状态与持久性 | 00 |
| 返回错误时，怎样证明状态没有改变？ | 契约与不变量 | 01 |
| 复制结构体后，其中的 map 一定独立吗？ | 值、引用与所有权 | 02 |
| 每次读写都加锁，为什么仍可能丢一次更新？ | 临界区与业务竞争 | 02–03 |
| 队列扩大十倍，为何未必提高吞吐？ | 处理能力与排队 | 03–04 |
| 同一个 uid 在两个游戏中，主键应怎样定义？ | 业务身份与数据模型 | 05 |
| 用新请求 ID 重领同一附件，幂等能否阻止多领？ | 传输身份与领域规则 | 06 |
| 写库后删缓存，为什么还可能读到旧值？ | 并发时序与派生状态 | 07 |
| 超时是否说明发奖没成功？ | 部分失败与结果未知 | 08 |
| 旧节点失去锁后，谁真正阻止它写库？ | 资格、代次与接收端校验 | 09 |
| P99 很小，是否代表所有用户都很快？ | 样本与分布 | 10 |
| Pod 不就绪时，Etcd 直连客户端一定停止请求吗？ | 生命周期与路由 | 11 |
| 新字段能解析，是否代表升级后业务兼容？ | 接口契约 | 12 |
| 检索到相关段落，为什么仍可能不能回答？ | 证据充分性与生成 | 14 |
| checkpoint 显示待执行，工具是否可能已经成功？ | 副作用与恢复 | 15 |

第 00–02 课薄弱就从第一阶段完整学习。已经熟悉某课时，可快速阅读基础，但仍完成一个独立变式和业务迁移。下游章节依赖的能力必须有证据，不能仅凭总分跳过。

<details>
<summary>诊断参考：重点检查哪些边界</summary>

内存没有自动恢复来源；错误与无副作用需要分别断言；值中可变引用仍可能共享；分开的读写锁未必覆盖完整状态转换；队列增加等待空间，不增加下游产能。

主键要反映租户范围；请求 ID 去重不能代替附件唯一领取；迟到读者可能回填旧缓存；超时可能发生在提交之后；旧 owner 需要接收端拒绝。

分位数留下了尾部；自定义路由有自己的传播机制；可解析与语义兼容不同；检索相关性不证明证据完整；流程记录可能落后于工具效果。

这些是核对方向。能复述后还应自己给出时间线、数据或测试来支持解释。

</details>

## 一次学习的过程

1. **回忆。** 合上上一课，写出一个机制及其成立条件。
2. **读需求。** 说明使用者、成功与失败代价，再决定本次要回答的问题。
3. **预测。** 在运行或看参考解释前，写下输入、执行顺序和预期状态。
4. **阅读与实验交替。** 学一个机制，就完成一个小观察；出现差异先解释再加新概念。
5. **独立变式。** 改输入、并发关系或故障点，检验理解是否可迁移。
6. **业务回顾。** 将结论用于个人案例，明确需要什么额外证据才能用于实际系统。

一次学不完可以停在机制边界，不要求把一整课连读到底。理论推导和画时间线也属于学习活动，但应与实际运行结果分别记录。

## 时间安排按实际掌握调整

24 周、每周 6–8 小时可作为日程示例，并非固定期限。基础薄弱的章节可以拆成多次学习；熟悉的章节通过变式后加快。扩写后的工程深化也不要求第一轮全部完成。

AI 语言基础可在数据阶段后预习；完整的检索、工具和评测仍需要身份、事务、恢复及指标知识。不要因为 AI 功能有现成框架就省略这些前置。

## 阶段通过的判据

沿用解释、预测、实验、迁移四项自评，每项 0–2：不能完成为 0，部分完成为 1，能独立完成并解释边界为 2。达到 6/8 且核心实验为 2，才视为该项实践通过。

这里的分数是课程自检约定。数据错乱、重复副作用、越权或旧节点覆盖等核心错误，应解决后再记为通过。缺少环境时可先完成理论，实验记为未验证，并保留后续任务。

## 与 AI 导师一起学习

```text
我学习到第 X 阶段、第 Y 课。
业务场景与本次要保护的规则：……
我对概念的解释：……
我预测的输入、顺序与结果：……
已经运行的命令和观察（未运行则明确标记）：……
我的推理或实现：……
请检查前置知识和推理，先指出最关键的一处问题，给一个提示。
等我修正后，再给一个改变条件的题目，最后让我迁移到业务场景。
请区分阅读、理论推导和已验证的实践，不代替我完成全部练习。
```

将结果记录到[进度页](./progress.md)的个人副本。业务资料使用脱敏描述与虚构输入，保留足以解释问题的规则和时序即可。
