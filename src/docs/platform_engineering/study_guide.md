## 从第一章起步

主线已调整为 IM，以 [OpenIM](./curriculum/im_reference.md)为项目参照。每章先解释当前 IM 需求与必要基础，再做小模型，具备前置后对照源码。已有任务与积分例子保留为机制补充，IM 长篇按新路线逐章适配。

完整系列按 [14 卷总纲](./curriculum/README.md)分类，实际阅读顺序使用[分阶段学习路线](./curriculum/learning_path.md)。A/B/C/D 是现有入门与衔接正文的课号，卷号和课号都不能直接当成必须逐卷通读的顺序。

课程默认你尚未掌握 Go，也不要求已经知道测试、HTTP、SQL 或 goroutine。详细学习从 [01.01 程序与工具链](./curriculum/01_go/01_program_toolchain.md)进入，再学 [01.02 类型与数据表示](./curriculum/01_go/02_types_data.md)。每章可以拆成多次学习，先完成一节的预测和练习，再继续。

接着阅读已完成的 [01.03 控制流与函数](./curriculum/01_go/03_control_functions.md)：第一次读一至五节和第八节，普通函数能解释后再深入递归与闭包。接着学习 [01.04 集合与文本](./curriculum/01_go/04_collections_text.md)和 [01.05 对象与指针](./curriculum/01_go/05_maps_structs_pointers.md)，再用 A07–A10 衔接尚未写完的长篇；短课可作回顾，不需机械重复。

[10.03 Git 起步](./curriculum/10_engineering/03_git_state.md)在会编辑文件后即可穿插；[10.01 可验证需求](./curriculum/10_engineering/01_verifiable_requirements.md)在普通函数基础之后学习。并行编写不会改变这些先修要求。

A 篇讲清语法和代码组织；B 篇讲清后端运行与协作的基础；C 篇讨论可靠性与平台机制。D05–D06 服务于主线的方案与综合实践，D01–D04 属于 AI 扩展。每次只选当前阶段需要的衔接内容，尚缺的长篇讲解按内容状态表记录。

集合基础之后，还可分别进入 [02.01 数学与成本](./curriculum/02_algorithms/01_discrete_cost.md)和 [03.01 数据与存储](./curriculum/03_systems/01_data_instructions_storage.md)。它们自行解释所需数学和系统定义，先完成第一遍的小模型，再回访概率、证明和缓存深化部分。

## 初学时先完成什么

第一周或前几次学习不必考虑分布式、容器和模型框架。先做到：保存正确文件、解释每一行代码、预测变量的变化、观察一个错误并修复。

S0 的入门自检，结合 01.01–01.02 与 A03–A04：

- 能区分终端命令与 Go 源码，并说出当前文件在哪里。
- 能解释 20、"20"、true 三种值的差别。
- 能按顺序推演一次 if 与三次循环。
- 能解释函数的输入与返回值，写出一个边界输入及预期。
- 修改输出后会先保存，再运行并核对。

如果暂时做不到，就在对应小例子上继续练习。这些是课程要教会的内容，不是进入课程前的考试。

## 每课使用同一种学习过程

1. **读小需求。** 说明这段程序要帮助谁完成什么。
2. **认识新概念。** 先理解名字、含义和最小例子。
3. **逐步预测。** 写出每一步变量、分支或消息的变化。
4. **阅读完整程序。** 找到 main、被调用函数、输入、结果和错误路径。
5. **动手核对。** 按说明准备自己的目录和文件，记录真实结果；只阅读时明确记为未执行。
6. **只改一个条件。** 用边界值、缺字段或不同顺序检验理解。
7. **总结原因。** 解释结果为何出现，以及当前例子还不能保证什么。

A 篇多数例子是完整程序。注明“片段”的代码需要放到指定函数或文件中，并补充提到的 import；不要将多个含 main 的完整版本同时放在同一个包。

## 按当前章节选择练习目录

独立章稿使用章内说明的个人目录，如 arena-hello、arena-types；每次只放入当前完整示例，片段按说明嵌入 main。以下是原有 A/B/C 课的目录约定，不要把它们与独立章稿的命令拼接。

A 篇使用个人创建的 go-course 模块，每课放在 a01、a02 等子目录。它帮助你亲手组织代码。

B、C 篇部分实践使用教材仓库里的 labs/platform_path。章节会提示何时切换；模块名、目录与命令不能从两个位置随意拼接。具体说明见[环境页](./environment.md)。

## 读不懂时怎样返回前置

先判断卡在语法、工具还是机制。例如 `func(context.Context, int) error` 看不懂，分别回到 A04 的函数类型、A07 的 error、B07 的 context；不要直接背下工作池代码。

`PRIMARY KEY(ns, uid)` 看不懂，先回到 B05 的表与主键；理解语法后，再用 C05 解释为何选择这两个身份字段。

C、D 各课开头有先修回顾表，也可通过[概念索引](./concept_map.md)查首次出现的位置。外部资料用于进一步核对，不承担缺失正文的补丁角色。

## 从“看懂”到“学会”

| 状态 | 可以据此说明什么 |
|---|---|
| 已阅读 | 见过讲解与参考答案 |
| 已推导 | 能在不运行时预测一个过程 |
| 已运行 | 按说明观察过具体例子 |
| 独立变式通过 | 改变条件后仍能解释和验证 |
| 能迁移 | 能把同一机制应用到另一项简单需求 |

不同状态分别记录。运行参考程序没有报错，并不等于自己的输入、并发或故障情形也被验证。

## 阶段验收与补学

先按[学习路线的阶段验收](./curriculum/learning_path.md)检查是否具备下一步前置：解释一个正常过程、一个失败过程，完成独立变式，并标记实际运行范围。尚无实验环境时继续理论学习，但相应工程验收保留待验证。

每学完一个小节就做一次预测和变式；阶段结束后隔一段时间重新解释关键规则。若失败来自语法，回基础课；若来自错误模型，回机制推导；若来自环境，查目录、依赖与配置，不同时重学所有内容。

下面保留原有短课的回顾目标：

A 篇：写一个任务积分程序，能解释数据、函数、错误、包和测试。

B 篇：解释 HTTP 请求如何到达函数，读写简单 SQL，正确等待并发工作，并说明通信与取消。

C 篇：围绕状态不变量分析事务、缓存、重试、故障与版本变化。

D05–D06：根据业务约束比较、交付和解释方案；D01–D04：按 AI 方向区分证据、生成和副作用。

复杂度逐层增加。没有数据库或集群环境时，可以先完成原理推导，把条件实践留作待验证；不强行用日历进度替代理解。
